CONTEXT / CHANGE FROM ORIGINAL PLAN
--------------------------------------------------------------------------------
- Results are LIMITED TO 10 companies per sector. No pagination needed.
- The input ticker is used only to resolve the sector name.
- The table shows the top 10 "hottest" companies in that sector.

--------------------------------------------------------------------------------
OVERVIEW
--------------------------------------------------------------------------------
A new page at /search/sector/[ticker] that:
1. Accepts a stock ticker in the URL (e.g., /search/sector/AAPL)
2. Resolves that ticker's sector via yahoo-finance2
3. Fetches up to 10 companies in that sector, sorted by a "Heat Score"
4. Displays results in a table for the end user

--------------------------------------------------------------------------------
DATA FLOW
--------------------------------------------------------------------------------
1. RESOLVE SECTOR
   - Call: yahooFinance.quoteSummary(ticker, { modules: ['assetProfile'] })
   - Extract: assetProfile.sector (e.g., "Technology")

2. FETCH SECTOR PEERS
   - Use yahoo-finance2 screener with a sector filter
   - Example filter structure:
     yahooFinance.screener({
       scrIds: 'most_actives',
       query: {
         operator: 'AND',
         operands: [{ operator: 'EQ', operands: ['sector', sectorName] }]
       }
     })
   - Fetch up to ~30 candidates, score them, then slice top 10

3. COMPUTE HEAT SCORE
   - Score each company on 4 normalized signals (each 0-100 across the result set)
   - Weighted average = final heatScore (0-100)

4. SORT & SLICE
   - Sort descending by heatScore
   - Return top 10 only

--------------------------------------------------------------------------------
HEAT SCORE FORMULA
--------------------------------------------------------------------------------
Signal                  | Weight | Yahoo Finance Field
------------------------|--------|------------------------------------------
% Price change today    |  35%   | regularMarketChangePercent
Volume vs avg volume    |  30%   | regularMarketVolume / averageDailyVolume3Month
52-week price position  |  20%   | (price - 52wLow) / (52wHigh - 52wLow)
Analyst upside          |  15%   | (analystTargetPrice - price) / price

Each signal is normalized 0-100 across all candidates in the result set.
Weighted average of normalized signals = heatScore (0-100).

--------------------------------------------------------------------------------
API ROUTE: GET /api/search/sector/[ticker]
--------------------------------------------------------------------------------
Example request:
  GET /api/search/sector/AAPL

Response shape (TypeScript):
  {
    sector: string;           // e.g., "Technology"
    resolvedFrom: string;     // The ticker used to resolve sector (e.g., "AAPL")
    companies: SectorCompany[];
  }

  interface SectorCompany {
    symbol: string;
    name: string;
    heatScore: number;                // 0-100 composite score
    regularMarketPrice: number;
    regularMarketChangePercent: number;
    marketCap: number | null;
    volume: number;
    avgVolume: number;
    volumeRatio: number;              // volume / avgVolume (e.g., 2.4)
    fiftyTwoWeekHigh: number;
    fiftyTwoWeekLow: number;
    fiftyTwoWeekPosition: number;     // 0-100%
    analystTargetPrice: number | null;
    analystUpside: number | null;     // % upside to target price
  }

Implementation steps in route.ts:
  1. Validate ticker using existing tickerSchema (src/utils/validationSchemas)
  2. Check request origin using checkOrigin (existing utility)
  3. Call quoteSummary(ticker, { modules: ['assetProfile'] }) -> extract sector name
  4. Call Yahoo screener filtered by that sector (~30 candidates)
  5. Compute normalized signal values and heatScore for each company
  6. Sort descending by heatScore, slice to top 10
  7. Return JSON response

Error handling:
  - Ticker not found / no sector -> 404 with descriptive message
  - Yahoo API failure -> 502 with fallback message
  - Follow existing createErrorResponse and createLogger patterns
    (same as used in src/app/api/stock/[ticker]/route.ts)

Caching:
  - Cache sector screener results for ~15 minutes
  - Use the same in-memory cache pattern as secCompanyCache

Rate limiting:
  - Apply stockDataLimiter (consistent with other stock routes)

--------------------------------------------------------------------------------
EDGE CASES & CONSIDERATIONS
--------------------------------------------------------------------------------
1. SECTOR NOT FOUND
   - Some tickers (ETFs, indexes) won't have a sector in assetProfile
   - Return helpful error: "No sector found for this ticker.
     Try a stock like AAPL or MSFT."

2. INPUT TICKER IN RESULTS
   - The input ticker is used only to resolve the sector
   - It may or may not appear in the top 10 results — that's fine

3. URL ENCODING
   - Sector names with spaces (e.g., "Consumer Cyclical") must be URL-encoded
     when passed between the API and page

4. LIMIT IS HARD-CAPPED AT 10
   - No pagination. Top 10 by heatScore only.
   - Fetch ~30 from Yahoo screener, score all, slice to 10

5. INSUFFICIENT DATA
   - If a company is missing analystTargetPrice or other fields,
     those signals should be treated as 0 (not excluded)

6. YAHOO RATE LIMITS
   - Use suppressNotices: ['yahooSurvey'] on YahooFinance constructor
     (consistent with other routes in this codebase)
