Auth & Approval Flow

Registration Flow

  1. User submits registration form (username, email, password)
  2. POST /api/auth/register validates input via Zod. Checks email + username uniqueness.
  3. Password hashed with bcrypt (10 rounds). User inserted with approval_status: 'pending'.
  4. Resend sends confirmation email to user and notification to admin.
  5. User cannot log in until an admin approves the account.

Admin Approval Flow

  1. Admin views pending users at /admin/users.
  2. Admin clicks Approve. PATCH /api/admin/users sets approval_status = 'approved'.
  3. Resend sends an approval notification email to the user.
  4. User can now log in. evaluateApprovalStatus() in auth.ts passes the check.

Login Flow

  1. User submits credentials (email + password).
  2. NextAuth CredentialsProvider calls loginLimiter rate check.
  3. Looks up user by email. Runs bcrypt.compare(password, hash).
  4. Calls evaluateApprovalStatus() — throws a descriptive error if pending or rejected.
  5. JWT created with id, role, approvalStatus. Redirects to home.

Password Reset Flow

  1. User submits email on /forgot-password. Always shows success message (anti-enumeration).
  2. If email found: SHA256 token generated, stored in password_reset_tokens (1-hour expiry). Resend emails reset link.
  3. User clicks link → /reset-password?token=…
  4. GET /api/auth/reset-password validates token.
  5. User submits new password. POST validates + consumes token, bcrypt hashes, updates user.

Session & Middleware

All routes except public ones are protected by NextAuth withAuth middleware defined in src/middleware.ts. The middleware reads the JWT session token from the cookie and redirects unauthenticated requests to /login. Server-to-server internal calls bypass authentication using an x-api-key header matching INTERNAL_API_KEY.

The JWT session token carries id, role, and approvalStatus. This avoids a database round-trip on every authenticated request.
Data Flow

Portfolio Data Flow

  1. Dashboard component mounts; calls GET /api/user/portfolio.
  2. API queries user_stocks JOIN stocks JOIN user_stock_predictions JOIN stock_brand.
  3. For each holding, fetches live price + analyst summary from Yahoo Finance.
  4. Returns enriched portfolio array with totals (costBasis, marketValue, unrealizedGain/Loss).
  5. Dashboard passes data to PortfolioSummary (KPI cards), PortfolioSection (card grid), and triggers refreshes when the user buys/sells.

Stock Detail Data Flow

  1. User navigates to /search/[ticker]. Page renders Stock component with ticker prop.
  2. Stock fires parallel requests: GET /api/stock_data/{ticker} (price, history, news, earnings, technicals) + GET /api/stock_data/{ticker}/gps + GET /api/dashboard/on?ticker=.
  3. Stock detail page assembles: price header, portfolio/watchlist action buttons (if applicable), StockSignalPanel, StockChart, TechnicalIndicatorsDisplay, analyst table, earnings table, StockNews.
  4. User can trigger prediction via StockPrediction (two-step: /api/stock_data/{ticker}/data → POST /api/prediction/{ticker}).

Watchlist Data Flow

  1. WatchlistSection calls GET /api/user/watchlist on mount.
  2. API fetches watchlist items, enriches each with Yahoo Finance live price and 6-month moving average from stocksdailyprice table.
  3. User can: (a) remove — DELETE /api/user/watchlist?stockId=, or (b) move to portfolio — opens PurchaseFromWatchlistModal which POSTs to /api/user/stocks.

Recommendations Data Flow

  1. RecommendationsSection calls GET /api/dashboard/recommendations.
  2. API fetches user's saved predictions from user_stock_predictions for all three scopes (portfolio, watchlist, discovery).
  3. Fetches current prices from Yahoo Finance to compare against predicted prices.
  4. Calls GET /api/worldbank (6-hour cached) to get macro dampeners: if unemployment is bearish, BUY threshold rises by 2%; globalHealthScore adjusts delta multiplier.
  5. Returns recommendations sorted by |deltaPct|. Tagged with scope.
AI Prediction Pipeline

Two-Step Architecture

The prediction system uses a two-step client/server architecture to separate data collection from model execution.

  1. Step 1 — Data fetch: StockPrediction component calls GET /api/stock_data/{ticker}/data, which assembles an enriched payload (historical prices, fundamentals, technicals, analyst data, macro context) formatted for the Python model. Result cached in stockDataCache.
  2. Step 2 — Model run: Component POSTs the payload to POST /api/prediction/{ticker}. Route checks predictionCache first. If no cache hit, validates ≥365 days history, then acquires a semaphore slot to cap concurrent Python spawns.
  3. Python execution: child_process.spawn runs scripts/predict_weighted_analysis.py, passing the JSON payload via stdin. The script outputs prediction JSON to stdout.
  4. Result handling: Route caches the result in predictionCache and fires an async POST to /api/prediction/save to persist the result in user_stock_predictions.
  5. Display: StockPrediction renders 4 horizon cards (1W/1M/3M/6M), an SVG trajectory chart with confidence bands, and a metric analysis accordion.

GPS Score (Global Performance Score)

A composite 0–100 score computed by the Python model. Combines 6 sub-scores:

Sub-scoreSource
Analyst UpsideAnalyst 12-month target price vs. current price
Revenue GrowthYoY revenue growth from earnings data
Earnings GrowthYoY EPS growth
52-Week Price ChangeCurrent price vs. 52-week low/high midpoint
MLP AlphaMulti-layer perceptron model alpha signal
AI ConfidenceModel prediction confidence level

GPS scores are stored in user_stock_predictions.gps_score (user-specific) and also in the recommended_stocks table (system-wide). The GET /api/stock_data/{ticker}/gps endpoint checks user predictions first, then falls back to system scores.

Card System Architecture

Discriminated Union Pattern

All stock display cards use a single discriminated union type StockCardModel with four variants. This allows a single StockCard entry point to route to the correct view without prop drilling.

// src/app/components/cards/types.ts

type StockCardModel =
  | SearchTrendingCard  // variant: 'search-trending' — price + hot rating, no actions
  | DeepmoneyCard       // variant: 'deepmoney'       — AI pick, price + prediction, no actions
  | PortfolioCard       // variant: 'portfolio'        — shares, GPS, actions: Buy More / Sell
  | WatchlistCard       // variant: 'watchlist'        — GPS, 6M MA, actions: Add to Portfolio / Remove

Card Rendering Chain

StockCard (React.memo)
  └─ BaseCardShell (hover, keyboard a11y)
       ├─ PortfolioCardView    (card.variant === 'portfolio')
       ├─ WatchlistCardView    (card.variant === 'watchlist')
       ├─ DeepmoneyCardView    (card.variant === 'deepmoney')
       └─ SearchTrendingCardView (card.variant === 'search-trending')

Each variant uses:
  ├─ CardHeader (symbol, price, change — portfolio or watchlist layout)
  ├─ CardMetricRow (label/value pairs)
  ├─ CardActions → ActionButton (primary/secondary/danger/neutral × sm/md)
  ├─ GpsTooltip → GpsBreakdownModal
  └─ formatters.ts (pure formatting functions)

Weighted Average Price Calculation

When a user buys additional shares of an already-owned stock, the purchase price is recalculated as a weighted average:

newAvgPrice = (existingShares × existingAvgPrice + newShares × newPrice)
              / (existingShares + newShares)
External Services

Yahoo Finance (yahoo-finance2)

  • Real-time quotes and daily change
  • Historical OHLCV price data
  • Analyst consensus + price targets
  • Earnings data (EPS actual vs. estimate)
  • Major indices (DJI, GSPC, IXIC, VIX)
  • Trending stocks
  • Industry/sector peer lists

World Bank API

  • US: GDP growth, CPI inflation, unemployment rate
  • Global trade volume + FDI flows (ETF GPS factors)
  • Multi-country risk index
  • Outputs a composite globalHealthScore
  • Hard-cached for 6 hours to avoid rate limits
  • Used by recommendations engine to dampen BUY thresholds when macro is bearish

Resend (Email)

All transactional emails. Three API keys via environment variables:

  • RESEND_API_KEY — auth emails (registration, approval, password reset)
  • RESEND_CONTACT_API_KEY — contact form emails
  • RESEND_FROM_EMAIL — sender address

Templates are inline HTML strings inside the route handlers.

SEC Company Tickers

The full SEC company ticker list is served as a static public asset at /company_tickers.json. The Search component fetches and filters this client-side (up to 200 results), so no backend search API is needed for ticker autocomplete.

Brand Color Enrichment

When a user adds a stock to their portfolio (POST /api/user/stocks), a background async call fires getBrandColorFromScript(ticker). This fetches the company's primary brand color and stores it in the stock_brand table. The color is then used as the accent bar at the top of each PortfolioCardView. This is a best-effort operation — it does not block the portfolio add response.

Key Utilities

In-Flight Request Deduplication

The stock data route (GET /api/stock_data/[ticker]) maintains a module-level Map:

const inflightRequests = new Map<string, Promise<Response>>()

If a second request for the same ticker arrives while the first is still awaiting Yahoo Finance, the second request is attached to the existing Promise instead of spawning a duplicate fetch. The entry is deleted from the Map once the Promise resolves.

A namespaced logger created with createLogger(namespace). Each API route creates its own named logger instance (e.g., createLogger('api/contact')). Exposes logger.info() and logger.error().
