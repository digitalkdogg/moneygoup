Technical Indicators & Signal Aggregation

This guide explains how raw OHLCV price data and a handful of fundamentals are turned into a single integer technical_score on a -14 to +14 scale. That score is the input to the technicalSignal component of the GPS score (20 of 100 points — see GPS Score).

There are two technical pipelines in the codebase:

  • JS pipeline — src/utils/technicalIndicators.ts. Produces the canonical totalScore (-14..+14) that gets stored as technicalScore and passed to GPS.
  • Python pipeline — scripts/predict_weighted_analysis.py. Computes a richer indicator set (MACD, Bollinger, Stochastic, ATR, EMA50, etc.) as features for the MLP regressor, and also receives the JS technicalScore back as external_tech_score to nudge the predicted-price impact.

Scoring Overview

The JS aggregator sums eight weighted sub-signals. The raw total has a theoretical range of -14 to +14 and is interpreted as follows:

Score Range Signal Color
Score ≥ 5 BUY Green
-4 ≤ Score ≤ 4 HOLD Gray
Score ≤ -5 SELL Red

Signal strength (0-100) is derived as min(100, |totalScore| * 10).

JS Signal Pipeline

Entry point: calculateTechnicalIndicators(historicalData, newsData, peRatio, pbRatio, marketCap) in src/utils/technicalIndicators.ts.

It expects an array of { date, open, high, low, close, volume } bars plus a sentiment-scored news array and three fundamentals. It returns:

TechnicalIndicators { sma20, sma50, rsi14, momentum, signal: 'BUY' | 'SELL' | 'HOLD', signalStrength: 0..100, signalReason: string, // human-readable AI summary scoreBreakdown: { ...per-metric scores and reasons, totalScore }, volatility: 'Low' | 'Medium' | 'High' | 'N/A' | null }

Internally it calls four pure helpers — calculateSMA, calculateRSI, calculateMomentum, and the volatility helpers from src/utils/volatility.ts — and then runs generateSignal to roll everything up.

Moving Averages (SMA)

SMA20 / SMA50 Crossover +3 / -3

The largest single component. Compares short-term trend to medium-term trend.

SMA(n) = mean( close[-n:] )
  • Bullish (+3): SMA20 > SMA50.
  • Bearish (-3): SMA20 < SMA50.
  • Neutral (0): equal, or insufficient data (< 50 bars).

Price vs SMA50 +1 / -1

Confirms whether the latest close sits on the bullish side of the 50-day trend line.

  • Above (+1): close > SMA50.
  • Below (-1): close < SMA50.

Relative Strength Index (RSI)

RSI (14-period) +2 / -2

Momentum oscillator using a simple-average gain/loss formulation (not Wilder's smoothing).

gains = max(close[i] - close[i-1], 0) losses = max(close[i-1] - close[i], 0) avgGain = mean(gains[-14:]) avgLoss = mean(losses[-14:]) RSI = 100 - 100 / (1 + avgGain / avgLoss)
  • Oversold (+2): RSI < 30 — contrarian buy signal.
  • Overbought (-2): RSI > 70 — selling pressure.
  • Neutral (0): 30 ≤ RSI ≤ 70.

Edge case: if avgLoss == 0 the function returns 100.

Momentum & Price Trend

10-Period Momentum +2 / -2

Absolute price difference vs the close from 10 bars ago.

momentum = close[-1] - close[-11]
  • Bullish (+2): momentum > 0.
  • Bearish (-2): momentum < 0.

Volatility Rating

Annualized Volatility +1 / -1

Computed in src/utils/volatility.ts from daily log returns scaled by √tradingDays, then bucketed by getVolatilityRating:

  • Low (+1): annualized vol < 20% — stability reward.
  • Medium (0): 20% ≤ vol < 50%.
  • High (-1): vol ≥ 50% — risk penalty.

News Sentiment

Average Article Sentiment +2 / -2

Mean of sentiment_score across the supplied news array (already normalized upstream by the financial-lexicon scorer).

  • Positive (+2): avg sentiment > 0.1.
  • Negative (-2): avg sentiment < -0.1.
  • Neutral (0): -0.1 ≤ avg ≤ 0.1, or no news.

Fundamental Valuation

Three optional fundamentals roll into a coreMetricsScore (the sum of the three sub-scores below). They are added to the technical total so the final aggregate is still a single -14..+14 integer.

P/E Ratio +1 / -1

  • Attractive (+1): P/E < 15.
  • Expensive (-1): P/E > 25.
  • Neutral or no data: 0.

P/B Ratio +1 / -1

  • Attractive (+1): P/B < 2.
  • Expensive (-1): P/B > 5.

Market Cap +1 / -1

  • Large-cap (+1): Market Cap > $200B (stability premium).
  • Small-cap (-1): Market Cap < $2B (risk discount).

Python Indicator Set (Feature Engineering)

The Python predictor in scripts/predict_weighted_analysis.py (function _calculate_features_internal) computes a deeper indicator set that is used as input features for the MLP regressor, not as a separate score. These are not used for the -14..+14 rollup, but they appear on the stock page's technical panel and in the JSON returned by the predict endpoint.

MACD 12 / 26 / 9

exp12 = EMA(close, span=12) exp26 = EMA(close, span=26) MACD = exp12 - exp26 MACD_Signal = EMA(MACD, span=9)

Surfaced in metric_analysis() output as bullish when MACD > MACD_Signal, else bearish.

Bollinger Bands (20, 2σ) window 20

sma20 = rolling_mean(close, 20) std20 = rolling_std(close, 20) BB_Upper = sma20 + 2 * std20 BB_Mid = sma20 BB_Lower = sma20 - 2 * std20

RSI (14) window 14

delta = close.diff() gain = rolling_mean( delta.where(delta > 0, 0), 14 ) loss = rolling_mean( -delta.where(delta < 0, 0), 14 ) RSI_14 = 100 - 100 / (1 + gain / (loss + 1e-9))

In the Python metric_analysis impact model, RSI > 75 dampens predicted upside (-1.5%) while RSI < 25 nudges it positive (+1.5%).

Stochastic Oscillator %K 14, %D 3

lo14 = rolling_min(low, 14) hi14 = rolling_max(high, 14) STOCH_K = 100 * (close - lo14) / (hi14 - lo14 + 1e-9) STOCH_D = rolling_mean(STOCH_K, 3)

Reported as overbought when %K > 80, oversold when %K < 20.

Average True Range (ATR-14) window 14

tr1 = high - low tr2 = |high - prev_close| tr3 = |low - prev_close| ATR_14 = rolling_mean( max(tr1, tr2, tr3), 14 )

Also reused downstream as a 1-week volatility proxy for the prediction interval.

Moving Averages

  • SMA_20 — 20-bar simple moving average
  • EMA_50 — 50-bar exponential moving average
  • SMA_200 / EMA_200 — long-trend filters
  • GoldenCross — boolean feature, SMA50 > SMA200

Note: the Python metric_analysis reports the SMA20 vs EMA50 relationship (not SMA20 vs SMA50 as the JS pipeline does), so the on-page Python summary can disagree slightly with the JS score's MA component.

52-Week Ratios & ROC

  • HiRatio_52w = close / rolling_max(close, 252)
  • LoRatio_52w = close / rolling_min(close, 252)
  • ROC_6m = pct_change(close, 126)
  • ROC_12m = pct_change(close, 252)

HiRatio_52w drives the high-beta stretch penalty: if beta > 2.5 and HiRatio_52w > 0.95, the predicted impact is dampened proportionally to how far beta exceeds 2.5.

Historical Volatility (30-day, annualized)

log_ret = ln( close / close.shift(1) ) HistVol_30 = rolling_std(log_ret, 30) * sqrt(252)

metric_analysis() — Predicted Price Impact

The Python metric_analysis function returns a JSON block consumed by the stock page (RSI/MACD/Stochastic/ATR/Bollinger panels) and computes a total_metric_impact multiplier that nudges the MLP's predicted price. Key behaviors:

Driver Trigger Impact
RSI extremes> 75 / < 25-1.5% / +1.5%
20-day trenduptrend / downtrend+2% / -1%
20-day growthcapped ±10%(growth/100) × 3%
News sentimentraw valuesentiment × 1.5%
External tech score (from JS)raw technicalScoremin(score × 0.5% × reliability, 2%)
Analyst consensusstrong sell..strong buyconsensus × 5% × reliability
Analyst target premiumweighted by coveragepremium × 5% × coverage_boost (max 1.5x)
Earnings beat streak0-4 quarters+1% per beat
High-beta near 52w highbeta > 2.5 & HiRatio > 0.95-(beta - 2.5) × 1.5%
Reliability scalar: min(analystOpinionCount / 40, 1.0). Both the external technical score and analyst consensus are scaled by this so a micro-cap with 4 analysts doesn't get the same uplift as a mega-cap with 40+.

The final total_impact is bucketed into one of five impact_classification labels:

  • very_bullish: > +0.08
  • bullish: > +0.04
  • neutral: -0.04 to +0.04
  • bearish: < -0.04
  • very_bearish: < -0.08

Feeding the GPS Score

The totalScore returned by calculateTechnicalIndicators() is persisted as technicalScore on the prediction record. At GPS-scoring time (src/utils/gps.ts) it gets mapped linearly from its native -14..+14 range into 0..20 GPS points:

const rawTech = metrics.technicalScore ?? 0 const m5 = Math.min(Math.max((rawTech + 14) / 28, 0), 1) * 20 // technicalSignal contribution to the GPS 0..100 total
