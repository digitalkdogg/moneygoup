Recommendation Engine: The 4-Bucket Strategy

GrowMyStocks' recommendation engine classifies stocks into four distinct buckets to provide tailored BUY/SELL signals. This system ensures that user-owned positions, monitored interests, AI-discovered opportunities, and ETF top-holding breakouts are each treated with the appropriate level of urgency and validation.

June 2026: A fourth bucket — ETF Holding — has been added. When a user holds ETFs in their portfolio, the /portfolio page now surfaces BUY recommendations for high-GPS individual stocks found inside those ETFs. See Bucket 4 below.
📊 Bucket 1: Portfolio

Positions that the user has officially purchased and confirmed. These represent real financial stakes and require the highest precision for signals.

  • Signals: Surfaces both BUY (add to position) and SELL (exit/trim) alerts.
  • Logic: Compares the AI 1-month prediction against the current live market price.
  • Badge color: Blue (bg-blue-100 text-blue-700)
is_purchased = 1 AND user_confirmed = 1 AND shares > 0 AND is_active = 1
Positive: +3% (default)
Negative: -3% (default)
👀 Bucket 2: Watchlist

Stocks that the user is actively monitoring but does not yet own. These items have been explicitly "confirmed" by the user (e.g., by clicking "Add to Watchlist").

  • Signals: Surfaces BUY alerts only.
  • Logic: Monitors for significant upward breakouts predicted by the AI.
  • Badge color: Amber (bg-amber-100 text-amber-700)
is_purchased = 0 AND user_confirmed = 1 AND is_active = 1
Threshold: +5% (default)
✨ Bucket 3: Discovery

High-potential stocks identified automatically by the deepmoney_sync.py engine. These appear as "unconfirmed" and do not show up in the "My Watchlist" section until the user interacts with them.

  • Discovery Logic: Stocks qualify for this bucket if they meet the following sync thresholds:
    • GPS Score > 10.0 (Sync Gate)
    • Dashboard Threshold > 25.0 (Surfacing Gate)
  • Target Users: Qualifying stocks are added for every user who has logged in within the past 7 days.
  • Signals: Surfaces BUY alerts only.
  • Badge color: Purple (bg-purple-100 text-purple-700)
is_purchased = 0 AND user_confirmed = 0 AND is_active = 1
Threshold: +5% (default)
🏭 Bucket 4: ETF Holding new

Individual stocks that are top holdings inside ETFs the user already owns in their portfolio. When the ML pipeline identifies a high-GPS breakout candidate inside one of the user's ETFs, it surfaces that holding as a direct BUY recommendation with a teal "etf holding" badge.

  • Signals: Surfaces BUY alerts only (holdings are pre-filtered by the ETF sync before being written to etf_stock_recommendations).
  • Source: Written by scripts/update_predictions.py during the ETF Holdings scan phase. The scan runs after standard portfolio predictions complete.
  • Detection: Each portfolio item is checked against Yahoo Finance's quoteType. If quoteType === 'ETF', the item is flagged is_etf: true and its top holdings are fetched via GET /api/stock_data/{ticker}/holdings.
  • Thresholds (all three must be met):
    • GPS score ≥ preset.gpsSurfaceValue (level 5 default 60) — resolved from ETF_HOLDING_ALGORITHM via models/etf_holding_presets.json
    • Predicted price change ≥ preset.minPredChangePct% (level 5 default 1.8%) — same source
    • AI confidence score ≥ ETF_HOLDING_MIN_CONFIDENCE (default 60) — independent of the preset
  • Card sub-label: Displays "In {ETF ticker}" (e.g., "In VGT") instead of the standard timestamp, so the user knows which of their ETFs contains this holding.
  • Badge color: Teal (bg-teal-100 text-teal-700)
  • Scope value: 'etf_holding'
  • Additional field: etfTicker (string) — the parent ETF that surfaces this stock.
Source: etf_stock_recommendations table
GPS ≥ preset.gpsSurfaceValue (L5=60)
predicted_change_pct ≥ preset.minPredChangePct (L5=1.8%)
confidence_score ≥ ETF_HOLDING_MIN_CONFIDENCE (default 60)
Preset resolved from ETF_HOLDING_ALGORITHM (1.0..10.0, default 5)
GPS: 60 (L5)
Pred change: +1.8% (L5)
Confidence: 60 (default)

UI Filtering on the Portfolio Page

The etf_holding scope is only enabled on the /portfolio page — the dashboard home page (/) does not include it. This is controlled by the scopes prop passed to RecommendationsSection.

The /portfolio page computes two derived values from the portfolio API response:

  • portfolioEtfTickers — array of symbols where is_etf === true (e.g., ['VGT', 'QQQ'])
  • hasEtfInPortfolio — boolean derived from portfolioEtfTickers.length > 0

When hasEtfInPortfolio is true, the page passes:

scopes={['portfolio', 'watchlist', 'etf_holding']} portfolioEtfTickers={portfolioEtfTickers}

Inside RecommendationsSection, a secondary client-side filter ensures etf_holding cards are only shown when r.etfTicker is contained in the portfolioEtfTickers set. This prevents watchlist-only ETF holding cards from leaking onto the portfolio recommendations grid.

If the user has no ETFs in their portfolio, the scopes array omits 'etf_holding' entirely and portfolioEtfTickers is not passed, so no ETF holding cards are rendered.

Environment Configuration

The signal thresholds for these buckets are configurable via .env.local / .env.production. As of v2.8, ETF holding tuning is collapsed under a single integer knob (ETF_HOLDING_ALGORITHM, 1–10, default 5) that resolves through models/etf_holding_presets.json. See App Overview · Env Vars for the full preset table and per-level values.
