Site-wide section-* class convention (2026-07-12): Every major UI region across the app — pages, dashboard components, /search/[ticker], legal pages, portfolio — carries a class="section-<kebab-slug>" on its parent <div>. Where a parent div wasn't available, a comment marker {/* section:section-<name> */} denotes the section start instead. The prefix makes sections greppable and gives CSS / DevTools / JS a stable handle on every landmark. See Style Guide · Utility Patterns for the naming rule.

ModelAccuracyWidget
src/app/components/ModelAccuracyWidget.tsx
Client
Headline analytics widget rendered on the home dashboard between the recommendations strip and the watchlist. Fetches GET /api/analytics/model-accuracy?skip_cache=true on mount and renders three KPI tiles for the currently-selected horizon: Overall Model Accuracy (a single global figure averaged across all resolved predictions and all 4 horizons, green tile), Proximity Accuracy (per-horizon MAPE-style score, blue tile, shown as "{pct}% ({resolved_count} predictions)"), and High Accuracy ≥95% (count of resolved predictions whose proximity score was at or above 0.95 for the selected horizon, amber tile, shown as "{n}/{resolved_count}"). Four horizon pills (1 Week / 1 Month / 6 Months / 1 Year) switch which horizon block from the API response is displayed; selected pill is blue (bg-blue-600), default is 1_month. When the API returns status: 'insufficient_data' (fewer than 30 resolved samples summed across the four horizons), the widget swaps to a blue info panel showing the server message and the current total_records count.

Card System
The card system uses a discriminated-union approach. A single StockCardModel type has four variants: search-trending, deepmoney, portfolio, watchlist. All cards are routed through StockCard, which switches on card.variant and dispatches to the appropriate variant view (SearchTrendingCardView / DeepmoneyCardView / PortfolioCardView / WatchlistCardView). The watchlist variant owns its own outer container (a compact 10px-radius tile per the design mockup) and bypasses BaseCardShell; the other three variants are wrapped in BaseCardShell.

Defines the discriminated union that drives the entire card system. All variants share CardBase (symbol, companyName, price, changePercent, optional changeAmount).

  companyName: string
  price: number | null
  changePercent: number | null
  changeAmount?: number | null

  variant: 'search-trending'
  hotRating: number | null
}

  variant: 'deepmoney'
  prediction: 'Bullish' | 'Bearish' | 'Neutral' | number | null
  gpsScore: number | null
  gpsBreakdown?: any | null
  timeframeLabel?: string | null   // e.g. "in 6 months"
  gpsHorizon?: '1_week' | '1_month' | '6_month' | '1_year'
}

interface PortfolioCard extends CardBase {
  variant: 'portfolio'
  sharesHeld: number | null
  analystFeedback: string | null
  analysts?: number | null
  gpsScore?: number | null
  gpsBreakdown?: any | null
  gpsHorizon?: '1_week' | '1_month' | '6_month' | '1_year'
  topAccentColor?: string
  predictedPriceHorizon?: number | null   // renamed from predictedPrice1m
  horizonLabel?: string                   // e.g. "1M", "6M"
  fiftyTwoWeekHigh?: number | null
  logo?: string | null
}

interface WatchlistCard extends CardBase {
  variant: 'watchlist'
  analystFeedback: string | null
  analysts?: number | null
  ma6m: number | null
  gpsScore?: number | null
  gpsBreakdown?: any | null
  gpsHorizon?: '1_week' | '1_month' | '6_month' | '1_year'
  isCompact?: boolean
  predictedPriceHorizon?: number | null   // renamed from predictedPrice1m
  horizonLabel?: string                   // e.g. "1M", "6M"
}

type StockCardModel =
  | SearchTrendingCard
  | DeepmoneyCard
  | PortfolioCard
  | WatchlistCard

AiTakePanel
src/app/components/AiTakePanel.tsx
Client Updated 2026-07-24
Green-tinted card (bg-[#f0fdf4]) on /search/[ticker] hosting the 🤖 Ask AI button. On click, fetches GET /api/prediction/[ticker]/ai-take and progressively renders the streaming response via a ReadableStreamDefaultReader — users see the first sentence in ~5-10s instead of waiting for the full paragraph. State machine: idle (button shown), loading (spinner), streaming (partial text + animated cursor), ready (full paragraph + ↻ Regenerate button), error (red banner with Retry). A 503 response sets a hidden flag for the session so the panel disappears when Ollama is down or AI_TAKE_ENABLED=off. On mount, automatically checks for a cached take via ?cache_only=1 — if one exists, renders it immediately without the user needing to click. Mounted from Stock.tsx right after the prediction / signal panels.
July 24, 2026: Added three classification badges rendered above the paragraph when the API returns the three X-AiTake-* classification headers. ClassificationBadges shows: (1) a colored filled pill for the quadrant (Quality Growth = emerald, Speculative = orange, Defensive = slate, Caution = red), (2) an outline badge for growth label (Low Growth / Moderate / Growth / High Growth), and (3) an outline badge for risk label (Low Risk / Moderate Risk / High Risk / Speculative). Each badge has a hover tooltip with a plain-English explanation. The response is now consumed as a streaming ReadableStream (model changed from gemma3:4b to gemma3:1b); added auto-load on mount via ?cache_only=1.

EarningsCalendar
src/app/components/EarningsCalendar.tsx
ClientNew 2026-07-24
Renders a 5-column earnings calendar for the next 5 business days on the /search page. Fetches from GET /api/earnings-calendar on mount. Each day is displayed as a DayCard showing: the date label (with a green "TODAY" pill for the current day), a company count, a pre-market/after-hours progress bar (PreAHBar), and up to 4 ticker previews. Each ticker entry shows a colored avatar (deterministic color from ticker hash), the symbol, company name, GPS score badge (if the ticker is in our system), and a time-of-day tag (PRE in orange / AH in violet). Overflow is handled via a "N more companies" button that opens a DayModal listing all entries for that day.
Sort order (applied by sortEntries()): GPS-scored tickers first (descending by score), then PRE timing, then unsupplied, then AH. Tickers without a GPS score are grouped by time-of-day only.
DayModal: Full-screen overlay with scrollable list of all earnings for a day. Closes on Escape key, backdrop click, or the X button. Locks body scroll while open. Each entry links to /search/{symbol}.
Skeleton state: While loading, 5 animated pulse cards render so the layout does not jump.

Profile
src/app/components/Profile.tsx
ClientAuth-aware
User profile page component. Fetches GET /api/user/profile on mount. Displays: avatar with user initials, account type badge, and for non-admin users: total lookup count, portfolio item count, and watchlist item count. Now also surfaces two Investment Strategy controls bound to user_investment_strategy:
  • Aggressiveness — a <select> with safe / neutral / aggressive options, each with a hint string explaining the effect on confidence floor, beta tolerance, GPS gate, and env-floor multiplier. Saved via a dedicated "Save Strategy" button (transactional PATCH). The Save button is disabled until aggressiveness differs from the originally-loaded value.
  • Investment Timeframe — four pill buttons (1 Week / 1 Month / 6 Month / 1 Year). Selecting a pill performs an optimistic PATCH: local state updates immediately, then a request is fired to PATCH /api/user/profile with only { investment_timeframe }; on failure the previous pill is restored. A hint string under the pills describes the active timeframe's ML-gate threshold.
