MoneyGoUp API Documentation

Comprehensive reference for all MoneyGoUp API endpoints, authentication models, response formats, and role-based data scoping. All endpoints are secured via NextAuth.js with session management or internal API key authentication. Endpoints returning potentially slow data include 15m–12h caching with source: 'livedata' | 'cache' reporting.

0 Fundamentals & Auth

Authentication & Security

Security Layer

Managed via NextAuth.js. All endpoints (except public assets) are protected by src/middleware.ts.

Security Policy:
  • Session: Uses JWT strategy with configurable SESSION_MAX_AGE (default 24h).
  • User Roles: Three role levels — user, superuser, admin — with progressive permission scopes.
  • Internal Bypass: Endpoints can be accessed via x-api-key matching DEEPMONEY_INTERNAL_SECRET.
  • Rate Limiting: Enforced per-IP via src/utils/rateLimiter.ts.
  • Approval Guard: Users must be approved by admins before accessing resource-heavy endpoints like dashboard.

POST /api/auth/register

User Identity

Creates a new user account with hashed passwords using bcryptjs. All new users default to role = 'user' and is_approved = 0.

Request: 
{
  "username": "john_doe",
  "email": "john@example.com",
  "password": "secure_password_123"
}
Response (201): 
{
  "user_id": 42,
  "username": "john_doe",
  "email": "john@example.com",
  "role": "user",
  "is_approved": 0
}

1 User Profile & Data Management

GET /api/user/profile

User Data: Authorization & Scoping

Fetches authenticated user profile information with role-based response structure. Returns different data shapes for admin, superuser, and user roles, enabling role-aware UI rendering and feature gating.

Authentication: Required. Returns 401 Unauthorized if session is invalid or missing. Data Scoping by Role:
Admin Role

Minimal profile response focused on account identity. No quota tracking — admins have unlimited access to all resources.

Superuser & User Roles

Full profile response with quota stats for enforcing role-based limits on watchlists, portfolios, and daily lookups.

Response Examples:

Admin Account (200 OK):

{
  "username": "admin_user",
  "accountType": "admin"
}

Superuser Account (200 OK):

{
  "username": "power_investor",
  "accountType": "superuser",
  "stats": {
    "lookupCount": 47,
    "portfolioItemCount": 12,
    "watchlistItemCount": 8
  }
}

Standard User Account (200 OK):

{
  "username": "jane_investor",
  "accountType": "user",
  "stats": {
    "lookupCount": 15,
    "portfolioItemCount": 5,
    "watchlistItemCount": 3
  }
}
Field Descriptions:
Field Type Roles Description
username string All Unique username (fetched fresh from DB, not from stale session)
accountType string All Role identifier: 'user', 'superuser', or 'admin'
stats object user, superuser Quota and usage counters
stats.lookupCount number user, superuser Total stock symbol searches executed by user
stats.portfolioItemCount number user, superuser Active purchased stock positions (shares > 0)
stats.watchlistItemCount number user, superuser Confirmed watched stocks (not yet purchased)
Error Responses:
Status Condition Response
401 No valid session or missing user ID { "code": "UNAUTHORIZED", "message": "..." }
500 Database or internal error { "code": "INTERNAL_ERROR", "message": "Error fetching user profile" }
Usage Notes:
  • All responses are synchronous (no polling required).
  • Username is fetched fresh from the database on each request to avoid stale session data.
  • Stats queries run in parallel for superuser/user roles to minimize latency.
  • Typical response time: 50–150ms for user/superuser, 20–50ms for admin.

2 Stock Data

GET /api/stock_data/[ticker]

Core: Consolidated Snapshot

The primary entry point for stock details. Supports comma-separated tickers for batch queries. Cached for 15 minutes. Returns real-time data or cache status.

Query Parameters:
Parameter Type Description
refresh boolean (optional) If true, bypasses cache and fetches fresh data
Response includes: source: 'livedata' | 'cache' Internal Dependencies:
  • Calls /api/stock_data/[ticker]/historical/1y
  • Calls /api/stock_data/[ticker]/news
  • Calls /api/stock_data/[ticker]/analyst
  • Calls /api/stock_data/[ticker]/earnings
  • Calculates Technical Indicators locally using calculateTechnicalIndicators.

GET /api/stock_data/[ticker]/data

Internal: Prediction Preprocessor

Assembles the deep 5-year data payload required by the MLP/LSTM Python engines. Cached for 15 minutes. Supports ?refresh=true.

Response includes: source: 'livedata' | 'cache' Logic Flow:
  • Fetches 5 years of OHLCV data.
  • Macro Integration: Calls /api/worldbank (propagates refresh).
  • Options: Calls /api/stock_data/[ticker]/options.
  • Performs Sector-based Imputation for missing fundamental metrics.

GET /api/stock_data/[ticker]/gps

GPS Score Lookup

Returns the GPS score and breakdown for a given ticker. Session-aware: always returns HTTP 200 and falls back gracefully through three sources so the UI never needs error handling.

Lookup priority:
  1. user_stock_predictions — if the session user has previously generated a prediction for this ticker, the most recent row is returned (source: 'user_stock_predictions').
  2. recommended_stocks — if no user prediction exists, the latest DeepMoney sync record for the ticker is used (source: 'recommended_stocks').
  3. none — if neither table has a score, returns the empty sentinel (source: 'none', all values null).
Authentication: Session is checked via NextAuth but the endpoint is publicly callable; unauthenticated requests skip step 1 and go directly to step 2. Validation: Ticker is validated against tickerSchema (Zod). Invalid tickers return the empty sentinel with HTTP 200 rather than a 4xx error. Response (200 OK — all cases): 
{
  "gpsScore": 72.4,
  "gpsBreakdown": {
    "analystUpside": 18.5,
    "revenueGrowth": 14.2,
    "earningsGrowth": 12.8,
    "fiftyTwoWeekChange": 11.0,
    "mlpUpside": 9.6,
    "mlpConfidence": 6.3
  },
  "source": "user_stock_predictions",
  "asOf": "2026-05-10T14:22:00.000Z"
}
Empty sentinel (no data found): 
{
  "gpsScore": null,
  "gpsBreakdown": null,
  "source": "none",
  "asOf": null
}
Field descriptions:
FieldTypeDescription
gpsScorenumber | nullOverall GPS score on a 0–100 scale.
gpsBreakdownobject | nullNamed component scores. Keys: analystUpside, revenueGrowth, earningsGrowth, fiftyTwoWeekChange, mlpUpside, mlpConfidence.
sourcestring'user_stock_predictions' | 'recommended_stocks' | 'none'
asOfstring | nullISO 8601 timestamp of the source record.
Used by: Stock component (single-ticker mount effect) and StockSignalPanel to display the score chip and top drivers.

Utility Endpoints

Granular endpoints used for targeted UI updates or internal data gathering. All support ?refresh=true to bypass cache.

Fetches OHLCV data for periods: 5d, 1m, 3m, 6m, 1y, 5y. Cached 15m. Returns cache_status and source.

Role-based allocation limits prevent resource exhaustion. When a user exceeds their quota, standardized error response is returned.

Role Limits:
Dimension User Superuser Admin
Watchlists 5 25 Unlimited
Portfolio Items 10 50 Unlimited
Daily Lookups 20 200 Unlimited

  "allowed": 10,
  "current": 10,
  "message": "You have reached your daily lookup limit. Upgrade to superuser for higher limits."
}

7 Common Patterns & Best Practices

Cache Control

Append ?refresh=true to any GET endpoint to bypass the cache and fetch fresh data from external APIs or the database. Useful for force-refreshing stale predictions or market data.

GET /api/stock_data/AAPL?refresh=true
GET /api/prediction/deepmoney?refresh=true

Error Response Format

All error responses follow a consistent structure for easier client-side handling.

{
  "code": "ERROR_CODE",
  "message": "Human-readable message",
  "correlationId": "req-12345-abcde",
  "errors": {
    "fieldName": ["error message 1", "error message 2"]
  }
}

Pagination

Endpoints returning lists support cursor-based pagination via limit and offset query parameters.

GET /api/stock_data/news?limit=20&offset=0
GET /api/dashboard/deepmoney-picks?limit=10&offset=20

Rate Limiting

All endpoints enforce per-IP rate limits. Headers indicate current state:

Header Description
X-RateLimit-Limit Total requests allowed in the window
X-RateLimit-Remaining Requests remaining in the current window
X-RateLimit-Reset Unix timestamp when the limit resets
