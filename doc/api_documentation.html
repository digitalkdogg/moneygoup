June 2026 changes summary: Horizon-aware response shapes are now standard across /api/user/portfolio, /api/user/watchlist, and /api/dashboard/recommendations — each returns a top-level horizonLabel matching the user's investment_timeframe.shortLabel. Portfolio and watchlist rows additionally expose predicted_price_horizon, predicted_change_pct_horizon, and confidence_score_horizon picked from the per-horizon columns in user_stock_predictions. POST /api/prediction/save accepts 8 new optional fields (predicted_change_pct_{1w,1m,6m,1y} and confidence_score_{1w,1m,6m,1y}) and writes them to user_stock_predictions; POST /api/prediction/[ticker] now forwards all 4 horizons of prices + 4 change_pct + 4 confidence to /api/prediction/save via savePredictionAsync. The user profile endpoint accepts PATCH to update the strategy. A new /api/analytics/model-accuracy endpoint powers the dashboard's ModelAccuracyWidget. /api/stock_data/[sector]/industry now sorts by GPS score (not the prior Heat composite), joining each sector leader against stock_gps_scores. DeepMoney sync injects all 11 canonical-sector top-25 lists nightly into a sector-leader override lane that bypasses the ranker keep-cut and writes a GPS row for each — see BR-14.4 / BR-14.5 / BR-14.6. Stocks the sync hasn't reached yet surface with gps_score: null and a placeholder in the UI. See the Strategy System doc for the full strategy model.
All routes are Next.js App Router Route Handlers (route.ts files). All authenticated routes validate the NextAuth JWT session. The checkOrigin() middleware is applied to most mutation endpoints. An internal bypass using the x-api-key header allows server-to-server calls. All authenticated data endpoints call checkApprovalGuard(userId) to re-verify approval status against the database on every request.
Middleware & Shared Utilities
src/proxy.ts Updated May 2026
NextAuth withAuth middleware. Protects all routes by default. The matcher excludes: /api/auth/*, /login, /register, /forgot-password, /reset-password, and all static assets (/_next/*, /favicon.ico, *.svg). Internal server-to-server requests bypass auth via an x-api-key header check. /api/unsubscribe is in the public paths list but is separately secured via HMAC-signed tokens.
CSP moved here (May 2026): The Content Security Policy is now generated per-request inside this middleware rather than as a static header in next.config.js. A cryptographically unique nonce is created via crypto.getRandomValues() for each request. The nonce is injected into the Content-Security-Policy header and passed to page components via the x-nonce request header. In production, the CSP uses script-src 'self' 'nonce-{nonce}' 'strict-dynamic' with no unsafe-eval.
checkOrigin() — src/utils/originCheck.ts
Validates the Origin header against NEXT_PUBLIC_NEXTAUTH_URL. Returns a 403 response if the origin does not match. Applied to nearly all POST/PATCH/PUT/DELETE endpoints.

GET /api/user/portfolio Auth required Updated 2026-06-15 src/app/api/user/portfolio/route.ts
Returns the authenticated user's full portfolio enriched with live market data. Queries user_stocks joined with stocks, user_stock_predictions, stock_gps_scores, and stock_brand.
Horizon-aware response (June 2026): The route reads the user's investment_timeframe via getUserStrategy(), resolves it to a column suffix (1w / 1m / 6m / 1y), and exposes three horizon-keyed columns on every row: predicted_price_horizon, predicted_change_pct_horizon, and confidence_score_horizon (all selected from the matching user_stock_predictions columns with predicted_price_1m as a price fallback). It then calls adjustGpsForHorizon(breakdown, changePct, confidence) to patch the cached 1-month GPS breakdown's mlpUpside component using the model's persisted per-horizon change/confidence (with a price-derived delta as a last-resort fallback for legacy rows). The top-level response now includes horizonLabel (from timeframeConfig.shortLabel) so the UI can label the breakdown correctly, alongside gpsHorizon on each row.
SQL pattern (dynamic columns by timeframe suffix)
SELECT
  usp.predicted_price_1m,
  COALESCE(usp.{priceColumn}, usp.predicted_price_1m) AS predicted_price_horizon,
  usp.predicted_change_pct_{sfx}     AS predicted_change_pct_horizon,
  usp.confidence_score_{sfx}         AS confidence_score_horizon,
  sgs.gps_score,
  sgs.gps_breakdown
FROM user_stocks us
JOIN stocks s ON us.stock_id = s.id
LEFT JOIN user_stock_predictions usp ON us.user_id = usp.user_id AND us.stock_id = usp.stock_id
LEFT JOIN stock_gps_scores sgs ON sgs.stock_id = us.stock_id

GET /api/dashboard/recommendations Auth required Updated 2026-06-15 src/app/api/dashboard/recommendations/route.ts
Aggregates GPS-scored predictions across four scopes — portfolio, watchlist, discovery, and etf_holding — and returns BUY/SELL recommendations sorted by GPS score descending. BUY/SELL action is determined purely by GPS thresholds and the user's strategy, not by delta percentage alone.
Top-level horizonLabel (June 15, 2026): The response now includes a top-level horizonLabel string matching the user's investment_timeframe.shortLabel (e.g. "in 6 months"). This lets the dashboard recommendation cards render a single horizon caption without re-resolving the strategy client-side.
Latest-snapshot ETF holdings (June 12, 2026): The ETF holding recommendations sub-query selects only rows where snapshot_date = (SELECT MAX(snapshot_date) FROM etf_stock_recommendations WHERE user_id = ?), replacing the prior rolling 7-day window. This mirrors the deepmoney-picks pattern and prevents stale picks from earlier update_predictions.py runs from leaking into the current card list.
Strategy-aware GPS (June 2026): All GPS thresholds are multiplied by the user's envFloorMultiplier (safe=1.05, neutral=1.0, aggressive=0.95). The sell threshold additionally shifts by sellThresholdShift (longer horizons tolerate more dip before a sell signal). The predicted-change gate is the strategy's predChangeGate multiplied by predChangeMultiplier (longer horizons require a larger absolute move). The GPS breakdown's mlpUpside component is patched to the user's horizon via adjustGpsForHorizon(), yielding a per-user GPS score rather than the cached 1-month baseline.

The route fetches World Bank data (6-hour cached) and applies a ±3 pt macro adjustment to each raw GPS score before threshold comparison. Unemployment bearish: −2 pts. Global health score above 70: +1.5 pts. Below 45: −3 pts. Clamped to [−3, +3].

Prediction Routes
POST /api/prediction/[ticker] Auth or internal API key Rate limited (LimitService) Updated 2026-06-15 src/app/api/prediction/[ticker]/route.ts
Runs the ML prediction pipeline for a single ticker. Spawns scripts/predict_weighted_analysis.py via Node child_process.spawn inside a semaphore. Results are cached in predictionCache and persisted asynchronously via /api/prediction/save.
All-horizons save forwarding (June 15, 2026): The internal savePredictionAsync() helper (lines ~248-290) now forwards every horizon of the Python script's output to /api/prediction/save — all 4 prices (predicted_price_1w/_1m/_6m/_1y), all 4 change percentages (predicted_change_pct_1w/_1m/_6m/_1y), and all 4 confidence scores (confidence_score_1w/_1m/_6m/_1y). Numeric values are sanitized through num()/positive() guards; non-finite or non-positive values are dropped so Zod validation on the save endpoint stays happy. Prices and the user_id are sent alongside the standard gps_score + gps_breakdown. The route's own response shape (gps_score, gps_breakdown, gps_horizon) is unchanged.
Analytics recording (June 2026): Immediately after a successful Python run, the route fires-and-forgets a recordPrediction() call (from src/utils/predictionRecorder.ts) that inserts a row into prediction_records with (symbol, predicted_at = CURDATE(), price_at_prediction, predicted_price_1w/_1m/_6m/_1y). The insert uses INSERT IGNORE so duplicate predictions for the same symbol on the same day are silently skipped. These rows are later resolved against actual prices and feed the /api/analytics/model-accuracy endpoint.
Strategy-aware outlook + GPS horizon (June 2026): For authenticated non-internal requests the route resolves the user's investment_timeframe via getUserStrategy(). The neutral 1m GPS baseline is always computed and persisted to stock_gps_scores, but the response also includes a per-user gps_score / gps_breakdown recomputed against the prediction matching the user's timeframe (predicted_change_pct_1w/_1m/_6m/_1y + matching confidence). The outlook query param defaults to 'all' when not provided; clients drive the user-facing horizon by sending the user's investment_timeframe.

POST /api/prediction/save Auth or internal API key Origin check Updated 2026-06-15 src/app/api/prediction/save/route.ts
Persists a prediction result to user_stock_predictions. Upserts on (user_id, stock_id). All four price horizons plus the new per-horizon change% and confidence columns are written when provided so the dashboard recommendations, portfolio, and watchlist routes can pick the right columns per the user's timeframe. The canonical GPS score is mirrored to stock_gps_scores (and historic snapshots appended to stock_gps_score_history) only when the score has actually changed at 1-decimal precision — avoiding spurious writes on repeat predictions.
New optional fields (June 15, 2026): The Zod schema now accepts 8 additional optional fields — predicted_change_pct_{1w,1m,6m,1y} and confidence_score_{1w,1m,6m,1y}. When present they are upserted directly into the matching user_stock_predictions columns. Field assignments use surgical guards (if (payload.X !== undefined)) so legacy callers that don't send them never overwrite existing values. The Zod schema in src/app/api/prediction/save/route.ts is the authoritative source of truth for the payload contract.

Analytics Routes
GET /api/analytics/model-accuracy Auth required 1-hour in-memory cache New 2026-06-12 src/app/api/analytics/model-accuracy/route.ts
Returns the headline model-accuracy metric that powers the dashboard's ModelAccuracyWidget. Operates in two modes: global (no symbol provided, aggregates every resolved row in prediction_records) and per-symbol (filtered to a single ticker). Accuracy is computed using a MAPE-style proximity formula across each horizon and then averaged across all horizons via a UNION ALL subquery.
MAPE-style proximity formula
accuracy_score = MAX(0, 1 - ABS(predicted - actual) / actual)
proximity_accuracy_pct = ROUND(100 × AVG(accuracy_score), 2)
total_accuracy_pct     = ROUND(100 × AVG(accuracy_score across all horizons), 2)
A prediction is considered "high accuracy" when its accuracy_score ≥ 0.95 (within 5% of actual).
