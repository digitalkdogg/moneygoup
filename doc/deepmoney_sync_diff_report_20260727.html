Algorithm Level Drift — Root Cause of the Divergence

Finding: DEEPMONEY_ALGORITHM differs between environments

Bluehost is running at algorithm level 2.2 on both captured runs; Local is running at algorithm level 1.7. This single env var (DEEPMONEY_ALGORITHM, resolved in src/utils/algorithmPreset.ts) drives rankerKeepPct, mlpConfidenceFloor, and volGateFloor for the entire pipeline — deepmoney_sync.py just echoes back whatever the API resolves server-side.

A higher level lets a larger slice of the ranked universe through (rankerKeepPct 11% on Bluehost vs. 8.5% locally), which alone accounts for most of the gap in surfaced/qualified stock counts: 188/162 surfaced on Bluehost vs. 103 locally, and 146/132 dashboard-qualified on Bluehost vs. 71 locally. This is expected behavior given the config difference — not a bug — but it means the two environments are not currently comparable for A/B validation of model changes unless the level is aligned first.

Local-Only Error: "Invalid JSON output from python"

⚠ 21 tickers failed prediction locally; zero failures on Bluehost

Thrown at src/utils/stockDataHelper.ts:119 when the predict_weighted_analysis.py subprocess exits with code 0 but its stdout can't be parsed as JSON:

try { resolve(JSON.parse(stdout)); } catch { reject(new Error('Invalid JSON output from python')); }

Failing tickers this run:

AEMAPDAPPBPCOSTCRHDELLDOWEQIXGSKLACLOWMDLZMGYMOMPCNEMNGNVSOWLPEP

The catch block discards the actual stdout content, so the reason the JSON parse failed (stray output mixed into stdout, truncated output, empty output, etc.) isn't visible in this log and can't be determined from it. This is flagged here as an open follow-up, not diagnosed further as part of this report.

Key Takeaways

  • Config drift, not a bug: Bluehost (level 2.2) and Local (level 1.7) are running different DEEPMONEY_ALGORITHM presets, which fully explains the gap in surfaced/qualified stock counts. Align the levels before using Local as a stand-in for Bluehost behavior.
  • Real local-only defect: 21 tickers fail prediction locally with "Invalid JSON output from python" with zero equivalent failures on Bluehost. Root cause is not visible in this log because the failing stdout is discarded on parse failure — worth a follow-up with stdout captured on failure.
  • Schema drift signal: Bluehost's is_etf column error and Local's loadCachedETFs argument error both point at the two databases having diverged; worth reconciling schemas.
  • Core picks agree: ~70% of Local's dashboard-qualified list also qualifies on Bluehost, so the underlying model/ranking logic is behaving consistently across environments — the volume difference is a config effect, not a logic difference.
