MoneyGoUp Web Application Overview

A brief end-to-end tour of the product, the stack, and how the pieces fit together. This page is the front door for the documentation set — every section ends with a pointer to a deeper doc when one exists.

1. What is MoneyGoUp

MoneyGoUp (brand: GrowMyStocks) is a personalized investing dashboard. It combines live market data, an in-house AI prediction model, and a unified GPS score to surface BUY / HOLD / SELL signals against the user's portfolio, watchlist, and a daily discovery feed.

The defining product idea is that every personalized number on screen is filtered through the user's own strategy — an investment_timeframe (1 week / 1 month / 6 month / 1 year) crossed with an aggressiveness setting (safe / neutral / aggressive). Two users looking at the same ticker on the same day can see different scores, different recommendations, and different price targets.

A secondary, but core, capability is that every AI forecast the platform produces is silently logged and graded against reality. Direction accuracy (did the model get up/down right?) is the headline quality metric exposed back to users on the dashboard.

4. Key User Flow

  1. Sign in. NextAuth resolves the session. New accounts must be admin-approved before this step succeeds — see Admin User Mgmt.
  2. Dashboard loads. Portfolio cards, watchlist cards, and a three-bucket recommendations feed (portfolio / watchlist / discovery) are aggregated from /api/dashboard and /api/dashboard/recommendations.
  3. Strategy is resolved. The user's investment_timeframe and aggressiveness are read from user_investment_strategy via src/utils/strategy.ts. Defaults are neutral + 1_month.
  4. GPS scores are patched per-horizon. Cached scores are read from stock_gps_scores and then adjusted with adjustGpsForHorizon (src/utils/gps.ts) so the displayed score matches the user's timeframe exactly — no separate row is stored per horizon.
  5. User drills into a ticker. /search/[ticker] renders the GPS signal panel + AI prediction card. Clicking the prediction CTA spawns the Python MLP inline through POST /api/prediction/[ticker].
  6. Predictions are recorded. Every successful inference fires recordPrediction() as a non-blocking side-effect, writing one row per (symbol, predicted_at) into prediction_records for later grading.

5. Personalization Model

The two strategy axes combine into a single StrategyConfig object that every personalized route reads before producing numbers.

  • Aggressiveness safe / neutral / aggressive — sets the gating bar (confidence floor, beta cutoff, GPS gate, predicted-change gate, and an env-floor multiplier of 1.05× / 1.0× / 0.95×).
  • Investment timeframe 1_week / 1_month / 6_month / 1_year — selects which predicted-price column to read from user_stock_predictions, sets the outlook passed to the Python MLP, scales the predicted-change gate, shifts the sell-side threshold, and chooses the DeepMoney ML gate and the UI display label.
  • Where it is applied Recommendation gates, DeepMoney candidate filtering, single-ticker GPS adjustment, and the prediction outlook are all derived from the same resolved config.
The single source of truth for the gate matrix, default fallback, and every multiplier is Strategy System. If a number on the dashboard looks "wrong" for a given user, the explanation almost always lives in their strategy row.

6. Background Jobs

Two Python scripts keep cached predictions and discovery picks fresh. Both authenticate to the Next.js API using the internal x-api-key header (src/utils/internalAuth.ts) and hit http://localhost:3001 directly to bypass the nginx 60-second proxy timeout.

  • scripts/update_predictions.py — Refreshes cached MLP predictions overnight (and on demand) so the dashboard does not have to spawn Python for every render.
  • scripts/deepmoney_sync.py — Runs the DeepMoney discovery pipeline: macro context fetch, recursive news discovery, ML validation gate, then commits to recommended_stocks and hot_etfs. Full breakdown in DeepMoney Sync.
