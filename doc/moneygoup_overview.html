MoneyGoUp Web Application Overview

A brief end-to-end tour of the product, the stack, and how the pieces fit together. This page is the front door for the documentation set — every section ends with a pointer to a deeper doc when one exists.

1. What is MoneyGoUp

MoneyGoUp (brand: GrowMyStocks) is a personalized investing dashboard. It combines live market data, an in-house AI prediction model, and a unified GPS score to surface BUY / HOLD / SELL signals against the user's portfolio, watchlist, and a daily discovery feed.

The defining product idea is that every personalized number on screen is filtered through the user's own strategy — an investment_timeframe (1 week / 1 month / 6 month / 1 year) crossed with an aggressiveness setting (safe / neutral / aggressive). Two users looking at the same ticker on the same day can see different scores, different recommendations, and different price targets.

A secondary, but core, capability is that every AI forecast the platform produces is silently logged and graded against reality. Direction accuracy (did the model get up/down right?) is the headline quality metric exposed back to users on the dashboard.

4. Key User Flow

  1. Sign in. NextAuth resolves the session. New accounts must be admin-approved before this step succeeds — see Admin User Mgmt.
  2. Dashboard loads. Portfolio cards, watchlist cards, and a three-bucket recommendations feed (portfolio / watchlist / discovery) are aggregated from /api/dashboard and /api/dashboard/recommendations.
  3. Strategy is resolved. The user's investment_timeframe and aggressiveness are read from user_investment_strategy via src/utils/strategy.ts. Defaults are neutral + 1_month.
  4. GPS scores are patched per-horizon. Cached scores are read from stock_gps_scores and then adjusted with adjustGpsForHorizon (src/utils/gps.ts) so the displayed score matches the user's timeframe exactly — no separate row is stored per horizon.
  5. User drills into a ticker. /search/[ticker] renders the GPS signal panel + AI prediction card. Clicking the prediction CTA spawns the Python MLP inline through POST /api/prediction/[ticker].
  6. Predictions are recorded. Every successful inference fires recordPrediction() as a non-blocking side-effect, writing one row per (symbol, predicted_at) into prediction_records for later grading.

Deeper dives: Prediction Workflow, Recommendation Buckets, GPS Score.

5. Personalization Model

The two strategy axes combine into a single StrategyConfig object that every personalized route reads before producing numbers.

  • Aggressiveness safe / neutral / aggressive — sets the gating bar (confidence floor, beta cutoff, GPS gate, predicted-change gate, and an env-floor multiplier of 1.05× / 1.0× / 0.95×).
  • Investment timeframe 1_week / 1_month / 6_month / 1_year — selects which predicted-price column to read from user_stock_predictions, sets the outlook passed to the Python MLP, scales the predicted-change gate, shifts the sell-side threshold, and chooses the DeepMoney ML gate and the UI display label.
  • Where it is applied Recommendation gates, DeepMoney candidate filtering, single-ticker GPS adjustment, and the prediction outlook are all derived from the same resolved config.
The single source of truth for the gate matrix, default fallback, and every multiplier is Strategy System. If a number on the dashboard looks "wrong" for a given user, the explanation almost always lives in their strategy row.

6. Background Jobs

Two Python scripts keep cached predictions and discovery picks fresh. Both authenticate to the Next.js API using the internal x-api-key header (src/utils/internalAuth.ts) and hit http://localhost:3001 directly to bypass the nginx 60-second proxy timeout.

  • scripts/update_predictions.py — Refreshes cached MLP predictions overnight (and on demand) so the dashboard does not have to spawn Python for every render.
  • scripts/deepmoney_sync.py — Runs the DeepMoney discovery pipeline: macro context fetch, recursive news discovery, ML validation gate, then commits to recommended_stocks and hot_etfs. Full breakdown in DeepMoney Sync.

7. Environment Variables

Every runtime knob the app reads, grouped by concern. Each entry lists what the knob does, its default, where in the code it's read, and one concrete example of turning it. Values shown in red are required — the app will fail to start without them. Vars marked (optional) have a code-level default and only need to be set when you want to override it.

System (auth, security, session, infrastructure)
NEXTAUTH_SECRET required
OverviewCryptographic key NextAuth uses to sign JWT session tokens. Rotating it invalidates every live session immediately.
Where usedsrc/lib/auth.ts (NextAuth options), every getServerSession() call.

OverviewCanonical URL of this Next.js instance. Single source of truth for NextAuth callback URLs, origin-check fallback, metadataBase, sitemap, and robots.

DeepMoney sync pipeline
DEEPMONEY_ALGORITHM optional · 5
OverviewThe single knob controlling deepmoney pipeline aggressiveness end-to-end. Float 1.0–10.0; lower = stricter, higher = more permissive. Resolves through models/algorithm_presets.json into four fields: rankerKeepPct, mlpConfidenceFloor, volGateFloor, analystStrongBuyThreshold. Fractional values (e.g. 1.5) interpolate linearly between adjacent integer rows. Replaces the retired DEEPMONEY_GPS_VALUE, DEEPMONEY_RECOMMENDATION_GPS_VALUE, DEEPMONEY_ANALYST_THRESHOLD, DEEPMONEY_USE_RANKER_GATE, and DEEPMONEY_TIER2_TOPK.
Where usedsrc/utils/algorithmPreset.ts (single read), src/app/api/prediction/deepmoney/route.ts (echoes the resolved preset in meta.algorithm), scripts/deepmoney_sync.py (reads back from meta.algorithm). Full detail: DeepMoney Sync.
Visible onThe dashboard's DeepMoney Picks widget, the DISCOVERY cards on /dashboard, and the per-user ETF Holding cards on /portfolio — all three are populated by the nightly deepmoney_sync.py run, which uses the resolved preset to gate every stock written to recommended_stocks. Lower the number = fewer cards everywhere; higher = more.
TuningMove the whole pipeline in one direction with one number: 
DEEPMONEY_ALGORITHM=1.5   # very strict: top ~7% by ranker, CS ≥ 72.5 (only top-bucket picks)
DEEPMONEY_ALGORITHM=5     # default: top 25%, CS ≥ 60
DEEPMONEY_ALGORITHM=8     # loose: top 60%, CS ≥ 45
Prediction / GPS scoring
GPS_PREDICTION_MAX optional · 3
OverviewSaturation point for the mlpUpside component of the GPS score. Formula: mlpUpside = clamp(predicted_change_pct / GPS_PREDICTION_MAX, -1, 1) × 20. Lower = component saturates faster (a +3% prediction pegs the full 20 pts); higher = component is more discriminating across a wider range.
Where usedsrc/utils/gps.ts (calculateGpsScore and adjustGpsForHorizon), scripts/update_predictions.py (calculate_gps_v3 mirror), src/app/api/stock_data/[ticker]/holdings/route.ts (inverse — recovers predicted_change_pct from stored breakdown).
Visible onThe GPS number on every card with a GPS score — portfolio cards on /portfolio, watchlist cards on /dashboard, BUY / SELL / DISCOVERY cards on /dashboard, the GPS panel on /search/[ticker], and the GpsBreakdownModal shown when a user taps a GPS number. Changing it shifts how aggressively prediction strength gets converted into the visible score.
Tuning 
GPS_PREDICTION_MAX=3      # default: tight 3% saturation
GPS_PREDICTION_MAX=15     # current prod: 15% saturation
GPS_BASELINE optional · 65
OverviewAnchor for the dashboard's BUY / SELL / DISCOVERY card rendering. BUY threshold = GPS_BASELINE; SELL = baseline + GPS_SELL_OFFSET; DISCOVERY = baseline + GPS_DISCOVERY_OFFSET. Then strategy envFloorMultiplier (safe×1.05, aggressive×0.95) scales BUY and DISCOVERY per user.
Where usedsrc/app/api/dashboard/recommendations/route.ts.
Visible onThe BUY cards on the /dashboard Recommendations strip, and the matching cards on /portfolio. Raising = fewer BUY cards render; safe-strategy users see an even tighter set than aggressive users for the same baseline.
TuningRaise to be more selective on BUY cards: 
GPS_BASELINE=62           # current: BUY at 62, scales 65.1 (safe) / 58.9 (aggressive)
GPS_BASELINE=75           # stricter: BUY only above 75
GPS_SELL_OFFSET optional · -20
OverviewOffset added to GPS_BASELINE to compute the SELL warning threshold. Almost always negative — SELL fires when GPS drops well below the BUY anchor. Not scaled by aggressiveness; warnings fire regardless of strategy.
Where usedsrc/app/api/dashboard/recommendations/route.ts.
Visible onThe SELL warning cards on /dashboard (red-bordered cards on the portfolio side). More negative = SELL warnings fire later (only on deeper score drops); less negative = warnings fire more eagerly.
Tuning 
GPS_SELL_OFFSET=-30       # SELL fires at GPS ≤ baseline - 30
GPS_DISCOVERY_OFFSET optional · +5
OverviewOffset added to GPS_BASELINE for the DISCOVERY card threshold. Set negative to put DISCOVERY below BUY (surface promising-but-unconfirmed picks). The code default of +5 puts it above BUY — usually the wrong direction; override it deliberately.
Where usedsrc/app/api/dashboard/recommendations/route.ts.
Visible onThe DISCOVERY cards on the /dashboard Recommendations strip (stocks the user doesn't own yet but the system thinks are interesting). More negative = more DISCOVERY cards surface; the default +5 means almost none ever show.
Tuning 
GPS_DISCOVERY_OFFSET=-25  # DISCOVERY fires at GPS ≥ baseline - 25
GPS_DEEPMONEY_MIN_SCORE optional · 65
OverviewRead-side GPS floor for the dashboard's DeepMoney Picks widget only. Filters which rows of recommended_stocks show in that widget. Independent from the BUY/SELL/DISCOVERY classification — a stock can clear this filter and still render as a non-BUY card.
Where usedsrc/app/api/dashboard/deepmoney-picks/route.ts.
Visible onThe dashboard's DeepMoney Picks widget only — the carousel of AI-curated stocks on /dashboard. Doesn't affect the BUY / SELL / DISCOVERY classification elsewhere on the page; it just filters which sync-persisted rows render in this specific widget.
TuningEffectively disable the widget filter (rely on the sync's own gates): 
GPS_DEEPMONEY_MIN_SCORE=4    # almost everything passes
GPS_DEEPMONEY_MIN_SCORE=65   # default: only the top tier shows
ETF_HOLDING_GPS_SURFACE_VALUE optional · 60
OverviewBaseline GPS threshold for an ETF holding to be surfaced as a per-user recommendation. Multiplied by the user's envFloorMultiplier per-strategy, so the effective floor is per-user.
Where usedscripts/update_predictions.py and src/app/api/stock_data/[ticker]/holdings/route.ts.
Visible onThe ETF Holding cards shown on /portfolio when the user owns an ETF (e.g. SPY, QQQ, VGT) — surfaces individual stocks inside those ETFs as picks. Higher = stricter, fewer cards; lower = more cards.
