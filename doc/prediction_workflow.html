AI Prediction Workflow & Algorithm

scripts/predict_weighted_analysis.py src/app/api/prediction/[ticker]/route.ts src/app/api/prediction/save/route.ts src/app/components/StockPrediction.tsx Updated 2026-06-03

This document details the end-to-end execution path and mathematical logic behind the Stock Prediction System (v3.3). The pipeline runs an MLPRegressor (sklearn) trained fresh per request on 5 years of enriched historical data, producing 1-week, 1-month, 6-month, and 1-year price targets with Monte Carlo uncertainty bands and an 18-month trajectory chart.

v3.3 changes (2026-06-03): Primary short-term outlook changed from 1-day to 1-week (T+5). MLP now has a 4-output head: [T+1, T+5, T+126, T+252]. The 1-week prediction is a blended output (30% MLP T+5 / 70% trajectory interpolation) with an ATR-based movement cap. Trajectory now anchors at t=0 (current price) with waypoints starting at t+5. 118 total FEATURE_COLUMNS including 13 newly added columns across 5 feature groups. Cache schema version bumped to v2. UI prediction cards now show 1-Week, 1-Month, 6-Month, 12-Month. Trajectory chart shows a gray "Now" dot at t=0. "Recalculate (skip cache)" button bypasses in-memory cache via ?refresh=true.

1 User Interaction

Frontend: StockSignalPanel.tsx + StockPrediction.tsx

The prediction workflow is initiated from the single-ticker view (/search/[ticker]) via one of two paths:

  • CTA button — user clicks "Show prediction details" in StockSignalPanel, which calls onGeneratePrediction, which calls predictionTriggerRef.current(), which calls StockPrediction's internal generate() via the triggerRef prop.
  • Multi-ticker comparison — each StockPrediction renders its own "Generate Prediction" button.

Requires 45 trading days of sequence context (SEQ_LEN = 45). Supports 15-minute server-side caching.

Recalculate Button (new v3.3)

After a prediction is displayed, a secondary text button labeled "↺ Recalculate (skip cache)" appears. Clicking it calls generate(true) which appends ?refresh=true to the prediction API call, bypassing the in-memory predictionCache and forcing the Python script to re-run.

Cooldown removed (2026-05-28): The previous 30-second per-user-per-ticker client cooldown countdown and the associated tickerCooldown Map on the server have been removed. Throttling is now handled solely by the role-based LimitService daily lookup quota and the predictionSemaphore concurrency cap.

2 Enriched Data Assembly

GET /api/stock_data/[ticker]/data — route.ts

Assembles a 5-year multi-dimensional dataset (~1,260 rows) that the Python script consumes as a single JSON payload. The script never makes outbound network calls itself.

Historical OHLCV

5 years of daily Open/High/Low/Close/Volume from yahooFinance.chart() with adj-close preference. Minimum 365 days enforced.

Fundamentals & Analyst Targets

PE, PB, margins, debt/equity, ROE, analyst target mean/median/high/low, opinion count, recommendation mean. Missing values are imputed from per-sector medians.

Options Market Data

IV, IV Rank, Put/Call Ratio fetched via /api/stock_data/[ticker]/options internal call.

Earnings Surprises

EPS and revenue surprise % averaged over the last 4 quarters (epsSurpriseAvg4Q, revenueSurpriseAvg4Q). Earnings date history is included for post-earnings drift calculation.

Short Interest

shortFloatPct and daysToCover from Yahoo Finance defaultKeyStatistics.

Insider Transactions

90-day window computed by extractInsiderMetrics(). Yields insiderNetSellRatio90d (net shares sold / shares outstanding, clipped to [-1,1]) and insiderTxCount90d. Option exercises excluded as directionally ambiguous.

Macro Series (11 symbols)

VIX, TNX, sector ETF, HYG, LQD, DXY, SPY, IRX, WTI crude, Copper, Wheat — all fetched in parallel and cached via macroCache.

World Bank Macro

GDP growth, inflation, consumption growth — annual, broadcast across all rows as scalar features.

Extended Feature Metrics new v3.3

EPS revision velocity (7-day), analyst upgrade/downgrade scores, pre/post-market gap percentages, 52-week positive ratio, institution ownership delta, peer relative strength — all included in featureMetrics object.

All data is returned as a single JSON payload with a dataQuality block tracking imputed fields, missing feature metrics, and history depth in years.

The endpoint has a 15-minute server-side cache (max 500 entries) and supports ?refresh=true to bypass it.

Both values are applied only to the most recent 63 rows of the feature matrix (approximately 3 months of trading days). All earlier rows receive a neutral value of 0.0 to avoid contaminating historical training samples with look-ahead data.

High-Beta / Valuation Stretch Penalty

Added to metric_analysis() in the heuristic adjustment layer. Applied when a stock has both a high beta (indicating volatility) and is trading near its 52-week high (indicating potential mean-reversion risk):

if beta > 2.5 AND HiRatio_52w > 0.95: stretch_penalty = 1.0 - ((beta - 2.5) * 0.015) total_impact += stretch_penalty - 1.0

At beta = 3.0 near a 52-week high, this applies a -0.75% impact to the final price target. At beta = 4.0, it applies -2.25%. The penalty is absent for beta <= 2.5 or stocks not near their 52-week high.

Market Regime Analysis (Phase 2-3)

A Gaussian Mixture Model (GMM) is fitted on a 10-dimension market vector at each run:

regime_vec_cols = ['VIX', 'HistVol_30', 'HYG_LQD_Ratio', 'RS_vs_SPY_20d', 'DXY_Return_20d', 'CurveSlope_10M3M', 'RollingMean_20d', 'RollingStd_20d', 'WorldBank_GDP', 'WorldBank_Inflation']

K is selected by select_regime_k() which evaluates K=3 and K=4 against two gates: minimum state population fraction ≥ 15% and temporal flip rate ≤ 30%. The first K that passes both gates is used. If neither passes, evaluation falls through to KMeans as a fallback.

The resulting regime labels and GMM posterior probabilities are added as one-hot (Regime_0–Regime_3), soft probability (Regime_Prob_0–Regime_Prob_3), and three interaction columns (Regime_x_PC_Ratio, Regime_x_HYG_LQD, Regime_x_RS_SPY). The four named states are: risk_on_trending, risk_off_stress, high_vol_choppy, low_vol_mean_reverting.

1-Week Prediction Blend Logic updated v3.3

The T+5 MLP output head is subject to high noise (5-day returns are ~90% noise; joint training with 6m/1y targets leaves the T+5 head under-trained relative to longer horizons). The final 1-week price is therefore a blend with a hard cap:

# Step 1: MLP T+5 raw output (after impact_multiplier) _mlp_1w_raw = inverse_close(pred_scaled[1]) * impact_multiplier # Step 2: Trajectory interpolation anchor (linear from current price toward 6m target) _traj_anchor_1w = current_price + (predicted_price_6m - current_price) * (T5 / T6) # T5=5, T6=126 → traj_anchor ≈ current_price + 3.97% of the 6m move # Step 3: Blend 30% MLP / 70% trajectory _blended_1w = 0.30 * _mlp_1w_raw + 0.70 * _traj_anchor_1w # Step 4: ATR-based cap — 5-day move cannot exceed 2× daily ATR scaled to 5 days _atr_1w = ATR_14 (last row) _max_move_1w = 2.0 * _atr_1w * sqrt(5) predicted_price_1w = clip(_blended_1w, current_price - _max_move_1w, current_price + _max_move_1w)

18-Month Trajectory Generation updated v3.3

The trajectory contains 19 waypoints, each with a midpoint price, lower bound, and upper bound. Waypoints are at trading-day offsets:

WAYPOINTS = [T5=5] + list(range(21, 379, 21)) # → [5, 21, 42, 63, 84, 105, 126, 147, 168, 189, 210, 231, 252, 273, 294, 315, 336, 357, 378]

The trajectory always starts at t=0 (current price) as a gray "Now" dot prepended in the UI by TrajectoryChart. The 19 backend waypoints then follow. This means the UI renders pts[0] = Now, pts[1] = t+5 (1 week), pts[2] = t+21 (1 month), pts[7] = t+126 (6 months), pts[13] = t+252 (12 months).

1-Month Earnings-Window Confidence Dampening

The 1-month confidence score is adjusted based on proximity to the next earnings date:

if days_to_earnings <= 14: cs1m = max(0, cs6m - 10) # near earnings: binary event risk, lower confidence else: cs1m = min(100, cs6m + 10) # standard: tighter horizon = slight boost cs1w = min(100, cs1m + 3) # 1-week: tighter than 1-month

The nextEarningsDate field from stockMetrics drives this calculation; if missing, _days_to_earnings defaults to 999 (far away), preserving the standard boost.

Confidence Score Formula

The base confidence score (cs6m) is built from four components, max 100 points:

ComponentMax ptsThresholds
CV-MAPE (holdout accuracy on T+126)40<5% → 40 pts; <10% → 30 pts; <20% → 15 pts; else 0
History depth25≥5y → 25; ≥4y → 20; ≥3y → 12; ≥2y → 5; else 0
Feature completeness200 imputed → 20; ≤2 → 14; ≤5 → 8; else 0
Analyst coverage15≥10 analysts → 15; ≥5 → 10; ≥1 → 5; else 0

Derived confidence scores:

  • cs1y = max(0, cs6m - 15) — longer horizon, wider uncertainty
  • cs1m = cs6m ± 10 — see earnings-window logic above
  • cs1w = min(100, cs1m + 3) — tightest primary horizon

7 Persistence Layer

POST /api/prediction/save — route.ts

After a successful prediction run, the API route fires an async (fire-and-forget) call to /api/prediction/save that persists the 1-month predicted price and GPS score to user_stock_predictions for the requesting user. The GPS score is computed from calculateGpsScore() using analyst upside, revenue growth, earnings growth, 52-week price change, ML alpha (predicted_change_pct_1m), and AI confidence (confidence_score_1m).

The save payload accepts both predicted_price_1w and predicted_price_1m as optional fields alongside the required predicted_price_1m. The DB column predicted_price_1w is populated when provided.

Internal (deepmoney sync) calls skip GPS computation and persistence.

Field naming (v3.3): The persistence route schema now accepts predicted_price_1w as an optional field. The route internally still requires predicted_price_1m for GPS calculation. No field was removed — predicted_price_1d was never persisted (the 1d prediction was only displayed in the UI).

Cache Architecture

scripts/prediction_cache/ — result cache + feature cache

The script maintains two cache layers in scripts/prediction_cache/:

  • Result cache (v2) — keyed by MD5(ticker + last_date + data_len + "v2"). Full prediction JSON stored as {key}.json. The schema version is embedded in the key string via CACHE_SCHEMA_VERSION = 2. Bumping this constant invalidates all stale v1 caches automatically without manual cleanup.
  • Feature cache — the full feature DataFrame stored as {ticker}_features_df.pkl. On the next run, if the new data is a forward extension of the cached data, only the new rows are computed using a 252-row lookback buffer. Broadcaster-scalar features (fundamentals, macro, insider) are updated in-place on the cached frame.

Server-side in-memory cache (predictionCache) stores prediction results keyed by {ticker}_{outlook}. Bypassed by ?refresh=true.

CPU usage is throttled via environment variables (OMP_NUM_THREADS=1, MKL_NUM_THREADS=1, etc.) set before numpy/sklearn import, and the process priority is lowered via os.nice(15).
