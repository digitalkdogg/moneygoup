AI Prediction Workflow & Algorithm

scripts/predict_weighted_analysis.py src/app/api/prediction/[ticker]/route.ts src/app/api/stock_data/[ticker]/data/route.ts Updated 2026-05-28

This document details the end-to-end execution path and mathematical logic behind the Stock Prediction System (v3.2). The pipeline runs an MLPRegressor (sklearn) trained fresh per request on 5 years of enriched historical data, producing 1-day, 1-month, 6-month, and 1-year price targets with Monte Carlo uncertainty bands.

v3.2 changes (2026-05-28): Insider selling features added to feature set; High-Beta/Valuation Stretch Penalty added to metric_analysis(); 1-month earnings-window confidence dampening; per-user 30-second cooldown removed from the prediction API; client-side countdown UI removed from StockPrediction.tsx.

1 User Interaction

Frontend: StockSignalPanel.tsx + StockPrediction.tsx

The prediction workflow is initiated from the single-ticker view (/search/[ticker]) via one of two paths:

  • CTA button — user clicks "Show prediction details" in StockSignalPanel, which calls onGeneratePrediction, which calls predictionTriggerRef.current(), which calls StockPrediction's internal generate() via the triggerRef prop.
  • Multi-ticker comparison — each StockPrediction renders its own "Generate Prediction" button.

Requires 45 trading days of sequence context (SEQ_LEN = 45). Supports 15-minute server-side caching.

Cooldown removed (2026-05-28): The previous 30-second per-user-per-ticker client cooldown countdown and the associated tickerCooldown Map on the server have been removed. Throttling is now handled solely by the role-based LimitService daily lookup quota and the predictionSemaphore concurrency cap.

2 Enriched Data Assembly

GET /api/stock_data/[ticker]/data — route.ts

Assembles a 5-year multi-dimensional dataset (~1,260 rows) that the Python script consumes as a single JSON payload. The script never makes outbound network calls itself.

Historical OHLCV

5 years of daily Open/High/Low/Close/Volume from yahooFinance.chart() with adj-close preference. Minimum 365 days enforced.

Fundamentals & Analyst Targets

PE, PB, margins, debt/equity, ROE, analyst target mean/median/high/low, opinion count, recommendation mean. Missing values are imputed from per-sector medians.

Options Market Data

IV, IV Rank, Put/Call Ratio fetched via /api/stock_data/[ticker]/options internal call.

Earnings Surprises

EPS and revenue surprise % averaged over the last 4 quarters (epsSurpriseAvg4Q, revenueSurpriseAvg4Q).

Short Interest

shortFloatPct and daysToCover from Yahoo Finance defaultKeyStatistics.

Insider Transactions new

90-day window computed by extractInsiderMetrics(). Yields insiderNetSellRatio90d (net shares sold / shares outstanding, clipped to [-1,1]) and insiderTxCount90d. Option exercises excluded as directionally ambiguous.

Macro Series (11 symbols)

VIX, TNX, sector ETF, HYG, LQD, DXY, SPY, IRX, WTI crude, Copper, Wheat — all fetched in parallel and cached via macroCache.

World Bank Macro

GDP growth, inflation, consumption growth — annual, broadcast across all rows as scalar features.

All data is returned as a single JSON payload with a dataQuality block tracking imputed fields, missing feature metrics, and history depth in years.

The endpoint has a 15-minute server-side cache (max 500 entries) and supports ?refresh=true to bypass it.

4 Feature Engine & Regime Detection

scripts/predict_weighted_analysis.py — build_features() / _calculate_features_internal()

Transforms the raw JSON into a 119+ column feature tensor (including 11 regime columns). Features fall into the following groups:

  • OHLCV core: Open, High, Low, Close, Volume
  • Technical indicators: MACD, Bollinger Bands, RSI-14, Stochastic-14, ATR-14, SMA-20/200, EMA-50/200
  • Long-horizon: HiRatio/LoRatio 52w, ROC 6m/12m, GoldenCross
  • Lag features: Close_lag_5/10/20, Volume_lag_5
  • Short-term momentum: ROC_5d, ROC_20d, Return_1d/5d/20d
  • Trend context: PriceToHigh/Low_20d, PriceToHigh_5d, EMA_Slope_10/20, VolumePriceTrend
  • Rolling statistics: RollingMean/Std/Skew/Sharpe_20d
  • Fundamentals (scalar broadcast): PE, PB, TrailingEPS, ForwardEPS, RevenueGrowth, EarningsGrowth, ProfitMargins, D/E, ROE, Beta, DivYield, AnalystPremium, AnalystPremiumWeighted, RecommendationMean
  • Macro series: VIX, VIX_20d_Avg, Treasury10Y/3M, SectorETF_60d_Corr
  • Credit risk proxy: HYG/LQD level and 20d momentum, HYG_LQD_Ratio
  • Dollar: DXY_Level, DXY_Return_20d
  • Curve slope: CurveSlope_10M3M
  • Relative strength: RS_vs_SPY_20d, RS_vs_SectorETF_20d
  • Commodities: WTI/Copper/Wheat return 20d + 60d beta
  • Volatility proxies: HistVol_30, VIX_RealVol_Ratio, PC_Skew_Proxy
  • Options: IV, IV_Rank, Put_Call_Ratio
  • Earnings & short interest: EPS_Surprise_Avg_4Q, Revenue_Surprise_Avg_4Q, ShortFloatPct, DaysToCover
  • Insider activity: InsiderNetSellRatio_90d, InsiderTxCount_90d new
  • Earnings-window flags: Earnings_In_Window, Days_Since_Last_Earnings, Days_To_Next_Earnings
  • Calendar: Month_Sin, Month_Cos, EarningsSeason
  • Derived sentiment: NewsSentiment, EarningsBeatStreak
  • World Bank macro (Phase 4): WorldBank_GDP, WorldBank_Inflation, WorldBank_Consumption, WorldBank_Real_GDP
  • Regime columns (Phase 2-3): Regime_0–3, Regime_Prob_0–3, Regime_x_PC_Ratio, Regime_x_HYG_LQD, Regime_x_RS_SPY

Insider Activity Features new

Two new columns added to FEATURE_COLUMNS (inserted in the Earnings Surprises & Short Interest block):

FeatureSource fieldRangeDescription
InsiderNetSellRatio_90dfeatureMetrics.insiderNetSellRatio90d[-1, 1]Net shares sold (sales minus purchases) divided by shares outstanding over the trailing 90 days. Positive = net insider selling; negative = net insider buying. Option exercises excluded.
InsiderTxCount_90dfeatureMetrics.insiderTxCount90d[0, ∞)Raw count of SEC Form 4 transactions in the trailing 90 days. Provides volume context for the net sell ratio.

Both values are applied only to the most recent 63 rows of the feature matrix (approximately 3 months of trading days). All earlier rows receive a neutral value of 0.0 to avoid contaminating historical training samples with look-ahead data.

The values are computed by extractInsiderMetrics() in route.ts, which fetches the Yahoo Finance insiderTransactions module and filters to transactions within the 90-day cutoff.

High-Beta / Valuation Stretch Penalty new

Added to metric_analysis() in the heuristic adjustment layer. Applied when a stock has both a high beta (indicating volatility) and is trading near its 52-week high (indicating potential mean-reversion risk):

if beta > 2.5 AND HiRatio_52w > 0.95: stretch_penalty = 1.0 - ((beta - 2.5) * 0.015) total_impact += stretch_penalty - 1.0

At beta = 3.0 near a 52-week high, this applies a -0.75% impact to the final price target. At beta = 4.0, it applies -2.25%. The penalty is unbounded below but practically small for beta values seen in normal equities. It is entirely absent for beta <= 2.5 or stocks not near their 52-week high.

Algorithm Flowchart

JSON Input → 119+ Feature Engineering
(OHLCV + Lag + ROC + Rolling Stats + Fundamentals + Macro + Credit + Commodities + Options + Insider + Regime)
↓
GMM/KMeans Regime Detection (K=3 or 4) + One-hot + Prob columns + Interaction terms
↓
MinMaxScaler → SEQ_LEN=45 sliding windows → MLP Training (Adam, early-stop, 20% holdout)
↓
Deterministic inference (1 pass) + Monte Carlo Dropout (12 passes, per-feature noise)
↓
Heuristic Weighting (metric_analysis + consumer multiplier + high-beta penalty)
↓
JSON Output: 1d / 1m / 6m / 1y prices, confidence scores, 18-month trajectory

Feature Caching & Incremental Updates

The script maintains two cache layers in scripts/prediction_cache/:

  • Result cache — keyed by MD5(ticker + last_date + data_len). Full prediction JSON stored as {key}.json. Subsequent requests for the same data snapshot skip the entire model pipeline.
  • Feature cache — the full feature DataFrame stored as {ticker}_features_df.pkl. On the next run, if the new data is a forward extension of the cached data, only the new rows are computed using a 252-row lookback buffer. Broadcaster-scalar features (fundamentals, macro, insider) are updated in-place on the cached frame.

CPU usage is throttled via environment variables (OMP_NUM_THREADS=1, MKL_NUM_THREADS=1, etc.) set before numpy/sklearn import, and the process priority is lowered via os.nice(15).

Market Regime Analysis (Phase 2-3)

A Gaussian Mixture Model (GMM) is fitted on a 10-dimension market vector at each run:

regime_vec_cols = ['VIX', 'HistVol_30', 'HYG_LQD_Ratio', 'RS_vs_SPY_20d', 'DXY_Return_20d', 'CurveSlope_10M3M', 'RollingMean_20d', 'RollingStd_20d', 'WorldBank_GDP', 'WorldBank_Inflation']

K is selected by select_regime_k() which evaluates K=3 and K=4 against two gates: minimum state population fraction ≥ 15% and temporal flip rate ≤ 30%. The first K that passes both gates is used. If neither passes, the evaluation falls through to KMeans as a fallback.

The resulting regime labels and GMM posterior probabilities are added as one-hot (Regime_0–Regime_3), soft probability (Regime_Prob_0–Regime_Prob_3), and three interaction columns (Regime_x_PC_Ratio, Regime_x_HYG_LQD, Regime_x_RS_SPY). The four named states are: risk_on_trending, risk_off_stress, high_vol_choppy, low_vol_mean_reverting.

5 MLP Training & MC Inference

sklearn MLPRegressor — hidden_layer_sizes=(256, 128, 64, 32)

A fresh MLP is trained per request on all available sequences. Architecture:

HyperparameterValueNotes
Hidden layers(256, 128, 64, 32)Widened to handle 119+ features
ActivationReLU
OptimizerAdamlr=0.001
Max iterations50Capped for speed
Early stoppingYesval_fraction=0.1, n_iter_no_change=8
Sequence length45 trading daysSEQ_LEN; sliding window via stride tricks
Targetsscaled Close at t+126, t+252Dual-head: 6m and 12m simultaneously

Validation uses a single 80/20 holdout (last 20% of sequences) rather than walk-forward cross-validation for speed. CV-MAPE from holdout feeds into the confidence score.

Monte Carlo uncertainty is generated via 12 forward passes (MC_RUNS=12) with additive Gaussian noise scaled per-feature to the standard deviation of the last 20 rows of each feature column. The 10th–90th percentile spread of MC outputs gives the trajectory confidence band.

1-Month Earnings-Window Confidence Dampening new

The 1-month confidence score is now adjusted based on proximity to the next earnings date:

if days_to_earnings <= 14: cs1m = max(0, cs6m - 10) # near earnings: binary event risk, lower confidence else: cs1m = min(100, cs6m + 10) # standard: tighter horizon = slight boost

Previously cs1m was always cs6m + 10. The new logic correctly reflects that a 1-month window that contains an earnings release carries more binary outcome risk than a 6-month window, and should therefore not receive an automatic confidence boost. The nextEarningsDate field from stockMetrics drives this calculation; if missing, _days_to_earnings defaults to 999 (far away), preserving the standard boost.

Confidence Score Formula

The base confidence score (cs6m) is built from four components, max 100 points:

ComponentMax ptsThresholds
CV-MAPE (holdout accuracy)40<5% → 40 pts; <10% → 30 pts; <20% → 15 pts; else 0
History depth25≥5y → 25; ≥4y → 20; ≥3y → 12; ≥2y → 5; else 0
Feature completeness200 imputed → 20; ≤2 → 14; ≤5 → 8; else 0
Analyst coverage15≥10 analysts → 15; ≥5 → 10; ≥1 → 5; else 0

Derived confidence scores:

  • cs1y = max(0, cs6m - 15) — longer horizon, wider uncertainty
  • cs1m — see earnings-window logic above
  • cs1d = min(100, cs1m + 5) — tightest horizon, highest confidence

7 Persistence Layer

POST /api/prediction/save

After a successful prediction run, the API route fires an async (fire-and-forget) call to /api/prediction/save that persists the 1-month predicted price and GPS score to user_stock_predictions for the requesting user. The GPS score is computed from calculateGpsScore() using analyst upside, revenue growth, earnings growth, 52-week price change, ML alpha (predicted_change_pct_1m), and AI confidence (confidence_score_1m).

Internal (deepmoney sync) calls skip GPS computation and persistence.
