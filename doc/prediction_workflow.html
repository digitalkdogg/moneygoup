AI Prediction Workflow & Algorithm

This master document details the complete end-to-end execution path and the mathematical logic behind the Stock Prediction System.

1 User Interaction

Frontend Component: StockPrediction.tsx

The workflow begins when the user clicks "Generate AI Prediction" on the stock detail page.

  • Lookback: The model requires 45 trading days of sequence context (optimized for <20s response).
  • Inputs: The UI passes the technicalScore (-14 to +14), recommendationKey, and recent newsArticles to be used as final weights.

2 Enriched Data Assembly

Backend Utility: GET /api/stock_data/[ticker]/data

Node.js acts as a high-speed aggregator, pre-assembling a 5-year multi-dimensional dataset (~1,260 rows).

Historical

Daily OHLCV bars.

Macro + Regime

VIX, Treasury, Credit Spreads (HYG/LQD), and DXY for regime detection.

Imputation

Fills missing PE/Margins using sector medians.

↓

3 API Gateway & Guards

Backend Handler: POST /api/prediction/[ticker]

The system enforces strict reliability gates before spawning the model process:

  • Origin & Auth: Validates session and CSRF.
  • Rate Limit: 30-second cooldown per user+ticker combo.
  • Data Gate: Rejects tickers with < 504 trading days (~2 years) of history.
  • Concurrency: Uses a Semaphore to cap active Python processes.

-- Input JSON Schema (Verbatim Payload)

The POST body is written verbatim to a temp file and passed to the Python script.

{
  "historicalData": [{ "date": "2024-03-08", "close": 150.0, "volume": 5000000, ... }, ...],
  "stockMetrics": { "peRatio": 25.4, "analystTargetMean": 185.0, "recommendationKey": "buy", ... },
  "macroData": { "vix": [...], "hyg": [...], "lqd": [...], "dxy": [...] },
  "newsArticles": [{ "title": "...", "sentiment_score": 4 }, ...],
  "technicalScore": 8

4 Feature Engine & Regime Detection

Python Engine: predict_weighted_analysis.py

The script transforms raw JSON into a 109-column feature tensor using specialized preprocessing:

  • Regime Selection (GMM): Fits a Gaussian Mixture Model to identify the current market regime (Risk-On, Risk-Off Stress, High Vol, Low Vol).
  • Interaction Terms: Computes crosses like Regime x Put_Call_Ratio to adjust sensitivity based on market state.
  • Scaling: All features are normalized to [0, 1] using MinMaxScaler.

5 MLP Training & MC Inference

Model: 256 → 128 → 64 → 32 (ReLU)

The system trains a fresh model on historical sequences (SEQ_LEN=45):

  • Monte Carlo Passes (12x): Gaussian noise (10% of recent σ) is added to features.
  • 1-Day Prediction: Linear interpolation between current price and 6-month target (1/126 trading days).

-- Key Constants (Speed Optimized)

Constant Value Purpose
SEQ_LEN 45 Lookback window. Balanced for speed and historical context.
N_EPOCHS 50 Capped training iterations with early stopping (n=8).
BATCH_SIZE 128 Optimized for fast gradient steps on CPU.
MC_RUNS 12 Statistical spread generation for confidence intervals.

7 Persistence Layer

Backend Utility: POST /api/prediction/save

To ensure insights are available for the dashboard, the resulting prediction is persisted to the database.

  • Trigger: After the Python process completes, the API asynchronously calls the save endpoint.
  • Data: Persists user_id, stock_id, and predicted_price_1m.
  • Dashboard Integration: These stored predictions directly drive the Real-time Recommendations engine and are displayed on individual Portfolio Cards to show the AI's expected trajectory.
  • Freshness: Updates the last_requested_at timestamp to ensure recommendations are based on the latest available intelligence.
