Database Documentation

This document provides a complete overview of the MoneyGoUp MySQL database schema, relationships, and the core business logic governing user data.

Core Business Logic

Portfolio vs. Watchlist vs. Discovery Logic

The system uses the user_stocks table to manage all stock relationships. Status is determined by a combination of is_purchased and user_confirmed:

  • Watchlist State: is_purchased = 0 AND user_confirmed = 1. The user has explicitly added this stock to their monitoring list. Shows in "My Watchlist".
  • Portfolio State: is_purchased = 1 AND user_confirmed = 1 AND shares > 0. The user owns a confirmed position.
  • Discovery State: is_purchased = 0 AND user_confirmed = 0. Stocks automatically identified by the AI engine. These generate recommendations but remain hidden from the user's primary watchlist until confirmed.
  • Closed Position: is_active = 0. Set when shares reach zero after being sold. The row is retained for history but excluded from active portfolio displays.

Authentication & Governance

User accounts are managed in the users table. Governance is enforced through registration approvals and role-based limits.

  • Approval Workflow: New users are created with approval_status = 'pending'. Only 'approved' users can establish a session. Administrators can 'reject' users with a specific reason.
  • Role-Based Limits: The system enforces quotas based on role (user, superuser, admin) for watchlist size, portfolio positions, and daily lookups. These are controlled by the role_limits configuration table.
  • Last Login: The last_login field is updated asynchronously every time a user successfully authenticates.
  • Password Reset: Users with a registered email can request a reset link via POST /api/auth/forgot-password. Tokens are stored (hashed) in password_reset_tokens and expire after 1 hour. Only approved accounts can receive reset emails.

user_investment_strategy NEW

Per-user investment strategy preferences. Upsert pattern: The Profile PATCH route runs an INSERT INTO user_investment_strategy (user_id, aggressiveness, investment_timeframe) VALUES (?, ?, ?) ON DUPLICATE KEY UPDATE aggressiveness = VALUES(aggressiveness), investment_timeframe = VALUES(investment_timeframe). The request body accepts either field individually (the timeframe pill UX sends only the field that changed) or both inside a { strategy: {...} } envelope (the dropdown's Save Strategy button). prediction_records NEW

Analytics ledger of multi-horizon model predictions, used to compute the headline accuracy KPIs surfaced by the ModelAccuracyWidget. Written fire-and-forget by recordPrediction() in src/utils/predictionRecorder.ts, called from the prediction API route handler and from the Python sync pipeline. The actuals (actual_price_*) are populated separately by the scheduled resolver job after each horizon elapses. Read by GET /api/analytics/model-accuracy (global and per-symbol).

ColumnTypeNotes
symbolVARCHAR(10)Stock ticker for the prediction. Part of the dedupe key.
predicted_atDATEDate the prediction was issued. Writer hard-codes CURDATE() in the INSERT so it pins to the local server day. Part of the dedupe key.
price_at_predictionDECIMAL(12,4)Spot price at prediction time. Baseline used by downstream MAPE computations.
predicted_price_1wDECIMAL(12,4)Predicted 1-week target. Nullable.
predicted_price_1mDECIMAL(12,4)Predicted 1-month target. Nullable.
predicted_price_6mDECIMAL(12,4)Predicted 6-month target. Nullable.
predicted_price_1yDECIMAL(12,4)Predicted 1-year target. Nullable.
actual_price_1wDECIMAL(12,4)Spot price one week after predicted_at. NULL until the horizon resolves. The model-accuracy route only scores rows where both predicted and actual are non-null AND actual > 0.
actual_price_1mDECIMAL(12,4)Spot price one month after predicted_at. Same resolution semantics as 1w.
actual_price_6mDECIMAL(12,4)Spot price six months after predicted_at. Same resolution semantics.
actual_price_1yDECIMAL(12,4)Spot price one year after predicted_at. Same resolution semantics.
updated_atTIMESTAMPAuto-updated when the resolver fills in actuals. MAX(updated_at) is surfaced in the API response as last_resolved_at.
Dedupe pattern: The writer uses INSERT IGNORE INTO prediction_records (symbol, predicted_at, price_at_prediction, predicted_price_1w, predicted_price_1m, predicted_price_6m, predicted_price_1y) VALUES (?, CURDATE(), ?, ?, ?, ?, ?). A UNIQUE index on (symbol, predicted_at) means a second prediction for the same ticker on the same day is silently ignored (the writer logs "Duplicate prediction (ignored)").
Accuracy formula: For each row/horizon the /api/analytics/model-accuracy route computes GREATEST(0, 1 - ABS(predicted - actual) / NULLIF(actual, 0)) (a clamped MAPE-style proximity score in [0, 1]). proximity_accuracy_pct is the per-horizon average ×100; total_accuracy_pct is the global average across all four horizons via UNION ALL; high_accuracy_count is the count of rows whose proximity ≥ 0.95. The endpoint requires at least 30 resolved rows summed across the 4 horizons before transitioning out of insufficient_data.

idINTPrimary Key. Auto-increment.
titleVARCHAR(512)Article headline. NOT NULL.
linkVARCHAR(1024)Canonical URL. NOT NULL. Unique — prevents duplicate ingestion.
pub_dateDATETIMEPublication date from source feed.
sourceVARCHAR(255)Feed source name.
sentiment_scoreDECIMAL(5,2)Computed sentiment (-1 to +1 scale).
created_atTIMESTAMPIngestion timestamp (auto).
user_stock_news

Junction table linking news articles to specific user-stock pairs. Enables per-user, per-stock news feeds.

ColumnTypeNotes
user_idINTFK to users.id.
stock_idINTFK to stocks.id.
news_idINTFK to news.id.
created_atTIMESTAMPAssociation timestamp (auto).
stock_brand

Stores branding assets for stocks (logo URLs, brand colours). Used by the UI to render stock cards with brand identity.

ColumnTypeNotes
stock_idINTPrimary Key. FK to stocks.id.
logo_urlVARCHAR(512)URL to the company logo image.
brand_colorVARCHAR(20)Primary hex brand colour (e.g. #00a8e0).
updated_atTIMESTAMPLast update timestamp (auto).
preview_leads

Captures contact form submissions from the public marketing preview page. Stores lead data for follow-up.

ColumnTypeNotes
idBIGINT UNSIGNEDPrimary Key. Auto-increment.
nameVARCHAR(120)Contact name. NOT NULL.
emailVARCHAR(255)Contact email. NOT NULL. Indexed.
companyVARCHAR(180)Company name (optional).
messageTEXTMessage body. NOT NULL.
ip_addressVARCHAR(64)Submitter IP address for spam/abuse tracking.
user_agentVARCHAR(500)Browser user-agent string.
created_atTIMESTAMPSubmission timestamp (auto). Indexed.
preview_visits

Logs anonymous page visits to the public preview/marketing site for traffic analytics.

ColumnTypeNotes
idBIGINT UNSIGNEDPrimary Key. Auto-increment.
ip_addressVARCHAR(64)Visitor IP. NOT NULL. Indexed.
user_agentVARCHAR(500)Browser user-agent string.
visited_atTIMESTAMPVisit timestamp (auto). Indexed. NOT NULL.
