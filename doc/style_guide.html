MoneyGoUp Design System

A comprehensive guide to the visual language and UI standards for the GrowMyStocks (MoneyGoUp) application. The system is built on Tailwind CSS v4 with brand tokens defined in src/app/globals.css and a small Tailwind config at tailwind.config.js. The goal is consistency, accessibility (WCAG 2.1 AA), and a clean financial aesthetic that puts data first.

Single source of truth: brand colors, button typography, and heading sizes are defined globally in globals.css. Components consume them via Tailwind utility classes — do not redefine these values per component.

Spacing & Layout

The app standardizes on Tailwind's default spacing scale. Common values you'll see across the cards layer:

  • gap-6 (24px) — primary grid gutter for the card grid.
  • gap-2 / gap-3 (8/12px) — internal card content gaps.
  • px-4 py-2 / px-5 py-4 — card header / body padding.
  • p-5 — full-size CardActions footer padding; px-3 pt-1 pb-3 when compact.
  • rounded-lg (8px) — buttons.
  • rounded-2xl (16px) — BaseCardShell outer container.
  • rounded-[10px] — Watchlist tile (custom 10px radius per mockup).
  • rounded-full (9999px) — bubbles & status pills.

Button Typography

All button font sizes and weights are controlled by a 3-tier global CSS system defined in src/app/globals.css. Explicit Tailwind font-size/font-weight classes are not used on buttons — the global rules are the single source of truth. The same tier classes apply to anchors (a.sm, a.xs) so links can be sized to match.

Tier 1 — Base (button)

button { font-size: 14px; font-weight: normal; cursor: pointer; }

Tier 2 — Small (button.sm, a.sm)

button.sm, a.sm { font-size: 12px; font-weight: 500; }

Used for: all card ActionButtons (Portfolio & Watchlist), which always include sm in their className.

Tier 3 — Extra Small (button.xs, a.xs)

button.xs, a.xs { font-size: 11px; font-weight: normal; }

Used for: chart period selectors in StockChart.tsx, PortfolioHistoryChart.tsx, and PortfolioCompareChart.tsx.

Important: do not add Tailwind text-* or font-* classes directly to <button> elements. The global CSS rules take precedence as the single source of truth for button typography.

Card Footer Conventions

  • Pin-to-bottom: the footer (or the divider above the footer) uses mt-auto so the bottom row stays anchored when the wrapper stretches to fill the row.
  • Divider: border-t border-gray-100 for Portfolio/DeepMoney, or a 1px bg-gray-100 spacer for Watchlist.
  • Horizon prediction label: dynamic — driven by the user's investment_timeframe. The card renders {horizonLabel} Pred (Watchlist) or {horizonLabel} pred (Portfolio). Falls back to '1M' only if no horizon is provided. Never hardcode "1M".
  • Chevron: a right-pointing chevron sits at the far right of the footer. The Portfolio variant swaps it for a red warning triangle when the model flags downside (using the shouldFlagDownside tuning in PortfolioCardView.tsx).

Card Grid Pattern

To make sibling cards in a row stretch to equal height, the grid uses two cooperating utilities: auto-rows-max on the grid + h-full on each wrapper. Each card shell also sets h-full internally so the inner flex column actually fills the wrapper.

// StockCardSection.tsx <div className={`${gridClass} gap-6 auto-rows-max`}> {data.map((item, index) => ( <div key={item.symbol} className="h-full" style={...}> {renderCard(item, index)} </div> ))} </div>

Combined with flex flex-col + mt-auto on the footer (see BaseCardShell and the per-variant views), this yields an even, magazine-style grid where every card in a row lines up at the bottom.

Common Utility Patterns

Layout

  • flex items-start justify-between — card header row (symbol on the left, price on the right).
  • grid grid-cols-3 gap-3 — three-column metric grid inside cards.
  • truncate max-w-[160-200px] — company-name overflow handling.
  • min-w-0 flex-1 — required on flex children that contain truncate content.

Borders & Dividers

  • border-t border-gray-50/100 — soft footer divider.
  • h-px bg-gray-100 — inline horizontal rule used in Watchlist.

Transitions

  • transition-all duration-200 — universal clickable-card hover (shadow + hover:-translate-y-1 lift). Applies to BaseCardShell, WatchlistCardView, SectorExplorer tiles, and the <Link> wrapper around MiniDataCard in RecommendationsSection.
  • transition-colors duration-200 — button hover.

Hover affordance rule: if the whole tile is clickable, it lifts with hover:-translate-y-1 + an expanded shadow. Table rows, presentational mini-cards (MiniDataCard in MarketOverviewCard), and informational tiles (Profile sections, IndexCard in MajorIndicesStrip) do not lift — the absence of the lift is itself a cue that the area is non-navigable.

Animation

The card grid animates each card in with a staggered slideUp keyframe (0.4s ease-out with a 0.05s delay per index) — defined inline in StockCardSection.tsx.

Bang-prefix override for global element rules (!text-[16px])

Tailwind v4 emits utility classes inside @layer utilities. Unlayered CSS in src/app/globals.css — for example the h3 { font-size: 1.375rem } rule at line 96 — wins over layered CSS regardless of selector specificity. When a Tailwind utility needs to beat a global element rule, prefix it with !, which compiles to an !important declaration and escapes the layer.

{/* Beats globals.css h3 rule */} <h3 className="!text-[16px] font-semibold text-blue-600">{article.title}</h3> <p className="!text-[14px] text-gray-500">{date}</p>

Live examples: src/app/components/StockNews.tsx:61,64 (article title + date on /search/[ticker]) and src/app/components/GpsTooltip.tsx:32 (!text-[11px] for the "View score" trigger). Reach for this pattern only when overriding a global element rule — do not use it to fight another utility class, since that indicates a specificity/order problem elsewhere.

Site-wide section-* class convention

Applied 2026-07-12. Every major UI region across the app — pages, dashboard components, /search/[ticker], legal pages, portfolio — carries a stable class="section-<kebab-slug-of-heading>" on its parent <div>. Where a parent div wasn't available (e.g. a fragment root), an HTML comment {/* section:section-<name> */} marks the section start instead.

  • Naming: section- prefix followed by the section's heading slugified to kebab-case (e.g. section-portfolio-summary, section-recommendations, section-technical-indicators).
  • Purpose: gives CSS, DevTools, and JS a stable, greppable handle on every landmark without polluting semantic markup. The prefix means grep -r "section-" enumerates every major region in the app.
  • Do not use section-* classes as styling hooks by default; treat them as identifiers. If a rule genuinely needs to target one region, that's fine, but the primary use case is discoverability and instrumentation.

Modal Standards

All modals in the application follow a standard accessibility layout enforced across every modal component (GpsBreakdownModal, BuyMoreModal, SellModal, etc.).

Outer container

bg-white rounded-2xl shadow-2xl w-full max-h-[90vh] flex flex-col overflow-hidden
  • max-h-[90vh] — caps the modal at 90% of the viewport height. Prevents the modal from overflowing off-screen on small displays.
  • flex flex-col — establishes the vertical flex context so the header stays pinned and only the content area scrolls.
  • overflow-hidden — clips the outer shell; scrolling happens on the inner body element only.

Scrollable body

p-6 overflow-y-auto flex-1
  • overflow-y-auto — enables scroll only on the content body, not the full modal. The header remains stationary.
  • flex-1 — allows the body to expand and fill the remaining vertical space after the header.

Header (GpsBreakdownModal)

The GpsBreakdownModal header uses a white background (bg-white inherits from the outer shell) with dark text (text-gray-900). There is no green-colored header on this modal. The header content is: an H3 "Global Performance Metric" heading, a subtitle with symbol / company / version, and a close button. This pattern should be followed for all full-detail modals.

Portal rendering

Modals that need to escape z-index stacking contexts (cards, sticky headers) are rendered via createPortal(content, document.body). This ensures the modal always sits above all other page content. Currently applies to: GpsBreakdownModal.

Keyboard & backdrop

  • Pressing Escape closes the modal (document.addEventListener('keydown', handler)).
  • Clicking the backdrop (the bg-black/40 overlay) closes the modal.
  • While open, document.body.style.overflow = 'hidden' prevents background page scroll. Cleaned up in the effect's return function.

Max width

Most detail modals are constrained to maxWidth: '480px' via inline style. The outer container is w-full so the modal is responsive below 480px.

Accessibility Standards

MoneyGoUp is committed to WCAG 2.1 Level AA compliance.

  • Contrast: brand greens are tuned to AA on white (Brand 700 = 5.0:1, Brand 800 = 6.8:1). All primary text and interactive elements maintain a minimum 4.5:1 contrast ratio.
  • Focus States: a 2px #2563eb outline with a 2px offset and an additional white "halo" via box-shadow — provided globally by .focus-ring and the :focus-visible rules in globals.css.
  • Skip Links: a "Skip to main content" link (.skip-link) is positioned off-screen and slides in on focus.
  • Keyboard: BaseCardShell and WatchlistCardView set role="button" + tabIndex={0} and handle Enter / Space.
  • ARIA: change-percent values include aria-label="Price up/down by N%"; downside-flag icons include both aria-label and a title; decorative icons set aria-hidden="true".
  • Semantics: strict heading hierarchy (one H1 per page) and consistent uppercase-tracked "section heading" treatment for major landmarks.
