GPS Score

The GPS Score (Global Performance Score) is a 0–100 composite metric that expresses how attractive a stock looks right now. It blends traditional fundamental signals with the output of the DeepMoney MLP prediction engine into a single number that users and the recommendation engine can act on at a glance.

One score, two inputs: four fundamental factors establish how healthy the business is, then the AI prediction layer adds a forward-looking signal. A stock can score well on fundamentals even without a fresh prediction, but the top of the range requires a strong MLP result.

What is the GPS Score?

GPS stands for Global Performance Score. It was designed to answer a single question quickly: how compelling is this stock right now, across both fundamentals and AI-driven price outlook?

The score runs from 0 to 100 and is always rounded to one decimal place. It is recalculated every time a prediction is run for a stock — whether triggered manually by a user, by the update_predictions.py background job, or by the deepmoney_sync.py discovery cycle. The most recent score for each stock is stored in stock_gps_scores (one row per ticker), making it instantly readable without per-user fan-out.

A GPS breakdown accompanies every score, showing exactly how many points each of the six components contributed, so users can see why a stock scored the way it did.

Score Ranges

The table below describes how scores translate to signal strength. These labels are used in the UI tooltip and breakdown modal.

Range Label Interpretation
0 – 24 Low Weak fundamentals and/or a flat or negative AI price outlook. Not flagged for recommendations.
25 – 49 Below Average Some positive signals present but not enough to clear recommendation thresholds.
50 – 64 Moderate Solid mixed picture. May appear in discovery recommendations depending on environment thresholds.
65 – 79 Strong Good fundamentals backed by a positive AI outlook. Likely qualifies for dashboard recommendations.
80 – 100 Exceptional High-conviction signal across all six components. Top of the DeepMoney discovery shortlist.
DeepMoney sync thresholds: The deepmoney_sync.py script uses two env-var-controlled GPS gates. Stocks must exceed DEEPMONEY_GPS_VALUE (default 10) to be recorded in recommended_stocks, and must exceed DEEPMONEY_RECOMMENDATION_GPS_VALUE (default 25) to be pushed to active user dashboards.

Score Components

The GPS score is built from six components totalling a maximum of 100 points. The first four are fundamental signals sourced from analyst and financial data. The last two come directly from the DeepMoney MLP prediction engine.

Component 1 — Fundamental
Analyst Upside
Max 19 pts
min(max(analystUpside / 0.30, 0), 1) × 19
Consensus analyst price target vs. current price, expressed as a fraction. A 30% upside to the analyst target earns the full 19 points. Negative upside scores 0.
Component 2 — Fundamental
Revenue Growth
Max 19 pts
min(max(revenueGrowth / 0.30, 0), 1) × 19
Year-over-year revenue growth rate as a decimal. 30% YoY growth earns the full 19 points. Shrinking revenue scores 0.
Component 3 — Fundamental
Earnings Growth
Max 19 pts
min(max(earningsGrowth / 0.25, 0), 1) × 19
Year-over-year earnings (EPS) growth rate as a decimal. 25% YoY growth earns the full 19 points. Uses a slightly lower ceiling than revenue to reflect EPS volatility.
Component 4 — Fundamental
52-Week Price Change
Max 19 pts
min(max(fiftyTwoWeekChange / 0.20, 0), 1) × 19
Trailing 52-week price return as a decimal. 20% price appreciation over the past year earns the full 19 points. Acts as a momentum proxy alongside the analyst view.
Component 5a — AI / MLP
MLP Predicted Upside
Max 19 pts
min(max(predicted_change_pct / GPS_PREDICTION_MAX, 0), 1) × 19
The 1-month percentage price change predicted by the DeepMoney MLP model. Scaled against GPS_PREDICTION_MAX (env var, default 3%). A 3% predicted gain earns the full 19 points.
Component 5b — AI / MLP
MLP Confidence Score
Max 5 pts
(confidence_score / 100) × 5
The model's self-reported confidence in its 1-month prediction, on a 0–100 scale. Full confidence (100) earns 5 bonus points. Acts as a quality weight on the AI signal.
Maximum possible score 19 + 19 + 19 + 19 + 19 + 5 = 100 pts

Full Formula

The canonical implementation lives in src/utils/gps.ts — calculateGpsScore(metrics, prediction). The Python equivalent is reproduced inline in scripts/update_predictions.py and scripts/deepmoney_sync.py (via the analyzer).

TypeScript (canonical — src/utils/gps.ts)

const predMax = parseFloat(process.env.GPS_PREDICTION_MAX ?? '3')

const m1  = Math.min(Math.max(analystUpside   / 0.30, 0), 1) * 19   // Analyst upside
const m2  = Math.min(Math.max(revenueGrowth   / 0.30, 0), 1) * 19   // Revenue growth
const m3  = Math.min(Math.max(earningsGrowth  / 0.25, 0), 1) * 19   // Earnings growth
const m4  = Math.min(Math.max(fiftyTwoWeekChange / 0.20, 0), 1) * 19 // 52-week change
const m5a = Math.min(Math.max(predicted_change_pct / predMax, 0), 1) * 19 // MLP upside
const m5b = (confidence_score / 100) * 5                              // MLP confidence

const gps = parseFloat(Math.min(m1+m2+m3+m4+m5a+m5b, 100).toFixed(1))

Python equivalent (scripts/update_predictions.py)

m1  = min(max(upside      / 0.30, 0), 1) * 19
m2  = min(max(rev_growth  / 0.30, 0), 1) * 19
m3  = min(max(earn_growth / 0.25, 0), 1) * 19
m4  = min(max(price_change / 0.20, 0), 1) * 19
m5a = min(max(pred_change_pct / 3.0, 0), 1) * 19   # GPS_PREDICTION_MAX hardcoded 3.0
m5b = (confidence_score / 100.0) * 5

gps_score = round(min(m1+m2+m3+m4+m5a+m5b, 100), 1)
Ceiling of 1: Every component uses min(…, 1) before multiplying by its max points, so a metric that far exceeds its threshold still scores the component maximum — it cannot over-contribute. Scores are always capped at 100 overall.

Data Sources

Each component draws from a different upstream source. All four fundamental inputs arrive via GET /api/stock_data/[ticker]/data → stockMetrics object, which assembles them from Yahoo Finance.

  • 📈
    analystUpside — Yahoo Finance financialData.targetMeanPrice vs regularMarketPrice. Expressed as a decimal (0.30 = 30%). Sourced via fetchYahooStockSummary().
  • 💰
    revenueGrowth — Yahoo Finance financialData.revenueGrowth. Year-over-year, already expressed as a decimal.
  • 📊
    earningsGrowth — Yahoo Finance financialData.earningsGrowth. Year-over-year EPS growth, decimal.
  • 📉
    fiftyTwoWeekChange — Yahoo Finance defaultKeyStatistics.52WeekChange. Trailing 1-year price return, decimal.
  • 🤖
    predicted_change_pct — DeepMoney MLP model output (scripts/predict_weighted_analysis.py). The predicted 1-month percentage price change. Passed back in the POST /api/prediction/[ticker] response.
  • 🎯
    confidence_score — DeepMoney MLP model output. Self-reported model confidence, 0–100. Also returned in the prediction response alongside the price forecast.

Where the GPS Score Appears

Stock detail page — Signal Panel

The StockSignalPanel component reads gpsData state from Stock.tsx (fetched from GET /api/stock_data/[ticker]/gps) and renders the score, a coloured label, and a top-3 component breakdown as progress bars. A "View score" button (renamed from "View breakdown" in May 2026) opens GpsBreakdownModal with all six components. In the card-level GpsTooltip component, the same action is triggered by a "View score" text button (previously a circled-i icon).

When a prediction completes, the GPS score is included directly in the prediction response payload, so Stock.tsx updates the displayed score immediately — without a round-trip re-fetch — eliminating the race condition that existed when the write was async.

Watchlist & Portfolio cards

GPS score and breakdown are joined from stock_gps_scores in the watchlist and portfolio queries via a LEFT JOIN and rendered in WatchlistCardView and PortfolioCardView respectively via the GpsTooltip component.

Dashboard recommendations

The recommendations engine (GET /api/dashboard/recommendations) uses GPS via COALESCE(sgs.gps_score, rs.gps_score). The score is included in each recommendation object so clients can display it alongside the BUY/SELL signal.

DeepMoney Picks

The DeepMoney discovery section reads GPS directly from recommended_stocks (populated during the sync cycle) and sorts picks by score descending.

Storage & Write Path

GPS scores are stored in two database tables:

  • stock_gps_scores — one row per stock, always reflecting the latest score (primary read source for all consumers).
  • stock_gps_score_history — append-only log, a new row is written only when the score changes.

Write optimisation — skip if unchanged

Before every GPS write, a single SELECT gps_score FROM stock_gps_scores WHERE stock_id = ? is executed. The incoming score is compared to the stored value at 1 decimal-place precision (matching the DECIMAL(5,1) column). If they match, all three writes are skipped:

  • The stock_gps_scores upsert
  • The stock_gps_score_history insert
  • The legacy recommended_stocks GPS sync

This is particularly valuable for update_predictions.py, which calls /api/prediction/save once per user per stock. For a stock held by N users, only the first call writes GPS; the remaining N−1 calls pay only for a cheap PK read.

Configuration

GPS behaviour can be tuned via environment variables in .env.local or .env.production.

VariableDefaultEffect
GPS_PREDICTION_MAX 3 The predicted 1-month percentage change that earns the full 19 MLP Upside points. Raising this makes component 5a harder to max out; lowering it amplifies even small predictions. Note: the Python scripts currently hardcode 3.0 independently.
DEEPMONEY_GPS_VALUE 10 Minimum GPS score to record a stock in recommended_stocks during the sync cycle (ML gate).
DEEPMONEY_RECOMMENDATION_GPS_VALUE 25 Minimum GPS score to push a stock to active user dashboards during the sync cycle (dashboard threshold).
Python/TypeScript parity: GPS_PREDICTION_MAX is read from the environment only in the TypeScript implementation (src/utils/gps.ts). The Python scripts in scripts/update_predictions.py hardcode the divisor as 3.0. If you change GPS_PREDICTION_MAX, update the Python scripts to match to keep scores consistent across all write paths.
