GPS Score v3.0

The GPS Score (GrowMyStocks Prediction Score) is a 0–100 composite metric that expresses how attractive a stock looks right now. Version 3.0 expanded the formula from 6 components to 8 components, adding a dedicated Technical Signal component (up to 20 pts) and an Analyst Consensus Rating (up to 9 pts) while rebalancing the weights of all other components. The result is a richer, more nuanced signal that no longer relies exclusively on analyst price targets and ML output.

GPS v3.0 — 8 components, 100 points. Combines ML prediction (25 pts), technical signals (20 pts), fundamentals (24 pts), analyst inputs (21 pts), and 52-week momentum (10 pts). TypeScript and Python implementations are kept in exact parity.

What is the GPS Score?

GPS stands for GrowMyStocks Prediction Score. It answers a single question quickly: how compelling is this stock right now, across ML prediction, technical signals, fundamentals, and analyst consensus?

The score runs from 0 to 100 and is always rounded to one decimal place. It is recalculated every time a prediction is run for a stock — whether triggered manually by a user, by the update_predictions.py background job, or by the deepmoney_sync.py discovery cycle. The most recent score for each stock is stored in stock_gps_scores (one row per ticker), making it instantly readable without per-user fan-out.

A GPS breakdown accompanies every score, showing exactly how many points each of the eight components contributed, so users can see why a stock scored the way it did. The breakdown is displayed via GpsBreakdownModal which is reachable from the "View score" button in both the stock detail page and dashboard cards.

Score Components (v3.0 — 8 components)

The GPS v3.0 score is built from eight components totalling a maximum of 100 points. The ML and AI components contribute 25 pts, technical signals 20 pts, fundamentals 24 pts, analyst inputs 21 pts, and momentum 10 pts.

Component 1 — ML / AI
ML Predicted Change (1m)
Max 20 pts
min(max(predictedChangePct1m / GPS_PREDICTION_MAX, -1), 1) × 20
1-month percentage price change predicted by the DeepMoney MLP model. Scaled against GPS_PREDICTION_MAX (env var, default 3%). A 3% predicted gain earns the full 20 pts. A negative prediction can push this component below zero, contributing to a lower overall score. A negative value here also sets bearishSignal = true in the GpsResult.
Component 2 — ML / AI
AI Model Confidence
Max 5 pts
(confidenceScore / 100) × 5
The model's self-reported confidence in its 1-month prediction, on a 0–100 scale. Full confidence earns 5 pts. Acts as a quality weight on the AI signal.
Component 3 — Fundamental
Revenue Growth YoY
Max 12 pts
min(max(revenueGrowthPct / 0.30, 0), 1) × 12
Year-over-year revenue growth rate as a fraction. 30% YoY growth earns the full 12 pts. Shrinking revenue scores 0.
Component 4 — Fundamental
Earnings Growth YoY
Max 12 pts
min(max(earningsGrowthPct / 0.25, 0), 1) × 12
Year-over-year earnings (EPS) growth rate as a fraction. 25% YoY growth earns the full 12 pts. Uses a slightly lower ceiling than revenue to reflect EPS volatility.
Component 5 — Technical
Technical Signal
Max 20 pts
min(max((technicalScore + 14) / 28, 0), 1) × 20
Raw technical score from calculateTechnicalIndicators(), ranging from -14 to +14. Mapped linearly to 0–20: a score of -14 maps to 0 pts; +14 maps to 20 pts. Computed server-side in /api/stock_data/[ticker]/data and returned as technicalScore at the payload root.
Component 6 — Analyst
Analyst Price Target Upside
Max 12 pts
min(max(analystUpside / 0.30, 0), 1) × 12
Consensus analyst price target vs. current price as a fraction. 30% upside earns the full 12 pts. Negative upside scores 0.
Component 7 — Analyst
Analyst Consensus Rating
Max 9 pts
CONSENSUS_POINTS[recommendationKey] (lookup table)
Fixed-point lookup based on the analyst consensus key from Yahoo Finance financialData.recommendationKey. Strong Buy = 9, Buy = 7, Hold = 4, Underperform = 2, Sell = 0. Defaults to Hold (4) if the key is missing. The Python script converts recommendationMean (1–5 scale) to a key via _recommendation_mean_to_key().
Component 8 — Momentum
52-Week Momentum
Max 10 pts
min(max(priceChange52w / 0.20, 0), 1) × 10
Trailing 52-week price return as a fraction. 20% price appreciation over the past year earns the full 10 pts. Calculated from defaultKeyStatistics.fiftyTwoWeekChange; if missing, the route derives it from 252 trading days of OHLCV history.
Maximum possible score (v3.0) 20 + 5 + 12 + 12 + 20 + 12 + 9 + 10 = 100 pts

Full Formula

The canonical implementation lives in src/utils/gps.ts — calculateGpsScore(metrics, prediction). The Python equivalent is calculate_gps_v3() in scripts/update_predictions.py. Both must remain in exact parity whenever the formula changes.

TypeScript (canonical — src/utils/gps.ts)

const predictionMax = process.env.GPS_PREDICTION_MAX ? parseFloat(process.env.GPS_PREDICTION_MAX) : 3

// 1. ML Predicted Change 1m (20 pts)
const m1 = Math.min(Math.max((prediction.predictedChangePct1m || 0) / predictionMax, -1), 1) * 20
// 2. AI Model Confidence (5 pts)
const m2 = ((prediction.confidenceScore || 0) / 100) * 5
// 3. Revenue Growth YoY (12 pts — full at 30%)
const m3 = Math.min(Math.max((metrics.revenueGrowthPct || 0) / 0.3, 0), 1) * 12
// 4. Earnings Growth YoY (12 pts — full at 25%)
const m4 = Math.min(Math.max((metrics.earningsGrowthPct || 0) / 0.25, 0), 1) * 12
// 5. Technical Signal (20 pts — raw -14..+14 mapped linearly to 0..20)
const m5 = Math.min(Math.max((rawTech + 14) / 28, 0), 1) * 20
// 6. Analyst Price Target Upside (12 pts — full at 30%)
const m6 = Math.min(Math.max((metrics.analystUpside || 0) / 0.3, 0), 1) * 12
// 7. Analyst Consensus Rating (9 pts — lookup)
const m7 = CONSENSUS_POINTS[metrics.recommendationKey ?? ''] ?? CONSENSUS_POINTS.hold
// 8. 52-Week Momentum (10 pts — full at 20%)
const m8 = Math.min(Math.max((metrics.priceChange52w || 0) / 0.2, 0), 1) * 10

const totalGps = m1 + m2 + m3 + m4 + m5 + m6 + m7 + m8
return {
  score: parseFloat(Math.min(Math.max(totalGps, 0), 100).toFixed(1)),
  bearishSignal: (prediction.predictedChangePct1m || 0) < 0,
  breakdown: { mlpUpside, mlpConfidence, revenueGrowth, earningsGrowth,
               technicalSignal, analystUpside, analystConsensus, priceChange52w }
}

Python equivalent (scripts/update_predictions.py — calculate_gps_v3())

prediction_max = float(os.getenv('GPS_PREDICTION_MAX', '3'))

m1 = min(max(predicted_change_pct / prediction_max, -1), 1) * 20
m2 = (confidence_score / 100) * 5
m3 = min(max(revenue_growth / 0.3, 0), 1) * 12
m4 = min(max(earnings_growth / 0.25, 0), 1) * 12
m5 = min(max((technical_score + 14) / 28, 0), 1) * 20
m6 = min(max(analyst_upside / 0.3, 0), 1) * 12
m7 = float(_CONSENSUS_POINTS.get(recommendation_key, _CONSENSUS_POINTS['hold']))
m8 = min(max(price_change_52w / 0.2, 0), 1) * 10

total = m1 + m2 + m3 + m4 + m5 + m6 + m7 + m8
score = round(min(max(total, 0), 100), 1)
bearish_signal = predicted_change_pct < 0
Ceiling of 1, floor of 0 (or -1 for m1): Fundamental and momentum components use min(…, 1) and max(…, 0) so they cannot over-contribute or go negative. The ML Upside component (m1) uses max(…, -1), allowing it to contribute negatively when the model predicts a price decline. The overall score is clamped to [0, 100].

Bearish Signal

Every GpsResult includes a bearishSignal: boolean field. It is set to true when predictedChangePct1m < 0, meaning the ML model forecasts a price decline over the next month. The field is also written to recommended_stocks.bearish_signal during the DeepMoney sync cycle.

This flag is surfaced in several places:

  • The Stock detail Signal Panel (StockSignalPanel) shows a red triangular warning banner reading "AI model predicts downside — the MLP signal is negative for this stock's 1-month outlook." whenever breakdown.mlpUpside < 0. This is checked on the breakdown object directly so the banner appears as soon as GPS data loads, without waiting for a prediction run.
  • The Portfolio card (PortfolioCardView) shows an "AI model predicts downside" warning badge whenever predictionChange < 0.
  • The Python sync script (update_predictions.py) prints a [gps] BEARISH SIGNAL log line and records the predicted change percentage when the flag is set.
  • The GPS Breakdown Modal shows the raw ML Prediction component score (which will be negative) alongside the overall score, giving users full transparency.
A bearish signal does not prevent the stock from scoring well overall — a stock with strong fundamentals, positive technicals, and strong analyst consensus can still score in the Buy range even with a slightly negative ML prediction. The signal is informational, not a hard gate.

Data Sources

All eight GPS inputs flow through the same pipeline: GET /api/stock_data/[ticker]/data assembles the full payload from Yahoo Finance, computes the technical score server-side, and returns everything the prediction engine and GPS calculator need.

  • 🤖
    predictedChangePct1m — DeepMoney MLP model output from POST /api/prediction/[ticker]. The predicted 1-month percentage price change. Stored in prediction_result.predicted_change_pct on the Python side.
  • 🎯
    confidenceScore — Also from the MLP model response. Self-reported model confidence (0–100). Stored alongside the price prediction.
  • 💰
    revenueGrowthPct — Yahoo Finance financialData.revenueGrowth. Year-over-year, decimal. Imputed from sector median if missing.
  • 📊
    earningsGrowthPct — Yahoo Finance financialData.earningsGrowth. Year-over-year EPS growth, decimal.
  • ⚡
    technicalScore — Computed server-side in /api/stock_data/[ticker]/data by calling calculateTechnicalIndicators(historicalData, [], peRatio, pbRatio, marketCap) (news omitted). The raw scoreBreakdown.totalScore (range -14 to +14) is returned at the top level of the payload as technicalScore. On the Python side, stock_data.get('technicalScore') reads it directly.
  • 📈
    analystUpside — Yahoo Finance financialData.targetMeanPrice vs regularMarketPrice. Expressed as a fraction. Stored in stockMetrics.analystUpside.
  • 📝
    recommendationKey — Yahoo Finance financialData.recommendationKey (string like "buy", "strongBuy"). Now returned at both stockMetrics.recommendationKey and at the payload top level as recommendationKey. The Python script prefers the top-level value and falls back to converting recommendationMean (1–5 float) via _recommendation_mean_to_key() for older cached payloads.
  • 📉
    priceChange52w — Yahoo Finance defaultKeyStatistics.fiftyTwoWeekChange. Trailing 1-year price return, decimal. If missing from Yahoo, derived from the last 252 rows of OHLCV history.

Where the GPS Score Appears

Stock detail page — Signal Panel

The StockSignalPanel component reads gpsData state from Stock.tsx (fetched from GET /api/stock_data/[ticker]/gps) and renders the score, a coloured label, and a top-3 component breakdown as progress bars. A "View score" button opens GpsBreakdownModal with all eight components and their exact point contributions. In the card-level GpsTooltip component, the same modal is triggered via a "View score" text button.

When the mlpUpside breakdown component is negative, the panel also displays a red triangular warning banner alerting the user to the negative AI outlook. The banner reads: "AI model predicts downside — the MLP signal is negative for this stock's 1-month outlook."

When a prediction completes, the GPS score is included directly in the prediction response payload, so Stock.tsx updates the displayed score immediately without a round-trip re-fetch.

Watchlist & Portfolio cards

GPS score and breakdown are joined from stock_gps_scores in the watchlist and portfolio queries via a LEFT JOIN and rendered in WatchlistCardView and PortfolioCardView respectively via the GpsTooltip component. The portfolio card also shows a red "AI model predicts downside" badge when predictionChange < 0.

GPS Breakdown Modal

GpsBreakdownModal (at src/app/components/modals/GpsBreakdownModal.tsx) displays all eight component scores in a clean list format (e.g., "ML Prediction (1m): 14.0 / 20"). The header uses an inline style (color: '#fff') on the ticker h3 to override a global CSS rule from globals.css that otherwise sets h3 to a dark foreground. The summary footer colour is determined by score: green (≥65), amber (45–64), or red (<45). The modal also decodes the numeric analystConsensus points back to a label string (e.g., 7 = "Buy") and displays it inline.

Dashboard recommendations

The recommendations engine (GET /api/dashboard/recommendations) uses GPS via COALESCE(sgs.gps_score, rs.gps_score). A macro adjustment of up to ±3 pts is applied based on World Bank unemployment signal and global health score before thresholds are evaluated. The GPS score is included in each recommendation object so clients can display it alongside the BUY/SELL signal.

DeepMoney Picks

The GET /api/dashboard/deepmoney-picks route reads GPS directly from recommended_stocks (populated during the sync cycle). It filters by GPS_DEEPMONEY_MIN_SCORE (default 65) and sorts picks descending by GPS score. Each pick also gets a recommendationLabel via getGpsLabel() for display in the UI.

Storage & Write Path

GPS scores are stored in two database tables:

  • stock_gps_scores — one row per stock, always reflecting the latest score (primary read source for all consumers).
  • stock_gps_score_history — append-only log; a new row is written only when the score changes.

Write optimisation — skip if unchanged

Before every GPS write, a single SELECT gps_score FROM stock_gps_scores WHERE stock_id = ? is executed. The incoming score is compared to the stored value at 1 decimal-place precision (matching the DECIMAL(5,1) column). If they match, all three writes are skipped:

  • The stock_gps_scores upsert
  • The stock_gps_score_history insert
  • The legacy recommended_stocks GPS sync

This is particularly valuable for update_predictions.py, which calls /api/prediction/save once per user per stock. For a stock held by N users, only the first call writes GPS; the remaining N−1 calls pay only for a cheap PK read.
