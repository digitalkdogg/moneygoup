A client triggers a POST request to the Next.js API route. The route validates auth, enforces a 30-second per-user/per-ticker cooldown, and checks a concurrency semaphore before spawning a Python child process. The full JSON payload is written to a UUID-named temp file, the Python script runs the MLP prediction pipeline, and its JSON stdout is returned directly to the client. The temp file is always deleted in the finally block.

Key Architectural Decision — Temp File vs. Stdin The JSON payload is written to a temp file rather than piped via stdin because large historical datasets (1,000+ rows × full payload) can exceed OS pipe buffer limits. The ticker symbol is passed as a CLI positional argument and is NOT embedded in the JSON. The temp file is cleaned up in the finally block even if the Python process crashes.
API Endpoint
POST http://localhost:3001/api/prediction/{ticker}
Accepts a JSON body with historical price data, stock metrics, macro data, news articles, and earnings history. Returns a full prediction result including 6m/1y price targets, an 18-month trajectory with uncertainty bounds, confidence scores, and technical indicator analysis.

Request Guard Chain (executed in order)

1
Origin Check
checkOrigin(request) validates the request comes from an allowed origin. Returns early if the check fails before any auth or body parsing occurs.
2
Session Authentication
getServerSession(authOptions) requires a valid NextAuth session with a non-null user.id. Returns 401 if no session is found. User identity (user.email) is used as the rate-limit key.
3
Ticker Validation
tickerSchema.parse(params.ticker) — Zod schema validates the URL path parameter. Returns 400 with the first ZodError message on failure.
4
Per-User Rate Limiting — 30 second cooldown
Key: ${email}-${ticker}. If the same user requests the same ticker within 30 seconds, returns 429 with a countdown in seconds. On every write, the map is scanned to evict expired entries (O(n)). A hard cap clears the entire map if it exceeds 5,000 entries to prevent unbounded memory growth in abnormal traffic.
5
Body Validation
Parses the JSON body and confirms: historicalData is a non-empty array with ≥ 504 rows, and stockMetrics is a non-null object. Returns 400 with specific messages for each failure case.
6
Concurrency Semaphore Check
predictionSemaphore.isFull() — if the maximum number of Python processes are already running, returns 503 immediately before acquiring a slot. Prevents memory pressure from pileups during slow predictions.
7
Record Cooldown & Acquire Semaphore Slot
Cooldown is recorded before spawning to prevent double-submit race conditions. The semaphore slot is then acquired, the Python process runs, and the slot is released in the finally block regardless of success or failure.

HTTP Response Codes

200 OK
Success
Prediction complete. Body is the full JSON prediction result.
400 Bad Request
Validation Error
Invalid ticker format, missing historicalData, or fewer than 504 rows.
401 Unauthorized
Auth Required
No valid session. User must be authenticated via NextAuth.
429 Too Many Requests
Rate Limited
Same user+ticker requested within 30s. Response includes seconds remaining.
500 Internal Error
Prediction Failed
Python process exited with non-zero code, or stdout was not valid JSON.
503 Unavailable
Busy
Concurrency limit reached. Retry in a moment.

monthly_trajectory construction The model only directly outputs 6m and 12m targets. Waypoints are built by linearly interpolating: current_price → mc_6m_mean → mc_12m_mean, then extrapolating to p18m = p12m + (p12m − p6m). Uncertainty bands are the MC 10th–90th percentile spread, widening proportionally with horizon (×1.5 at 18m vs 12m).

Known Limitations & Design Notes

No temporal memory in the MLP. sklearn's MLPRegressor has no recurrent connections. Temporal context is provided entirely through the 60-day flattened window and the v3 lag/ROC features. An LSTM or Transformer would handle sequence order intrinsically without requiring explicit lag feature engineering.


Monte Carlo ≠ true Dropout uncertainty. Real MC Dropout perturbs model weights by keeping dropout active at inference. Here, uncertainty is estimated by perturbing input features with calibrated Gaussian noise. This reflects input sensitivity, not weight uncertainty, and will generally underestimate true epistemic uncertainty.


Fundamentals are row-constant. PE ratio, EPS, margins, and other stockMetrics values are broadcast identically across every historical row. The model cannot learn how fundamentals evolved over time — only their current snapshot is visible.


18-month trajectory is interpolated, not predicted. The model outputs only 6m and 12m targets. The full 18-month trajectory is built by linear interpolation between those anchors and linear extrapolation beyond 12m. It indicates trend direction but is not a month-by-month forecast.


RMSE approximation. The code computes rmse = sqrt(cv_mae²), which equals cv_mae. True RMSE requires summing squared per-sample errors before taking the root. The reported RMSE in the output is therefore redundant with MAE.


Single holdout vs. walk-forward CV. v3 replaced 3-fold walk-forward cross-validation with one 80/20 holdout split for speed. This produces a noisier MAPE estimate and means the confidence score is based on a single fold rather than an average across multiple time-based folds.


In-memory rate limiting. The tickerCooldown Map lives in Node.js process memory. It is not shared across multiple server instances in a load-balanced or serverless deployment. A Redis-backed store would be needed for correct multi-instance rate limiting.
