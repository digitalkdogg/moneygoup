Overview

Every authenticated user has a UserStrategy — a pair of preferences stored in the user_investment_strategy database table. These preferences are loaded on each API request and used to adjust recommendation thresholds, GPS scores, and predicted-price references in real time. The underlying ML model output and stored GPS data are never mutated; the strategy system applies lightweight transformations at read time.

The single source of truth for all strategy logic is src/utils/strategy.ts. This module exports the type definitions, the lookup tables, the validators (isValidAggressiveness, isValidTimeframe), getUserStrategy(userId), and the resolveStrategy() function that every route and the Python batch script depend on.

The 3 aggressiveness levels × 4 timeframes = 12 combined configurations are computed on the fly by resolveStrategy(); nothing is materialised.

Dimension 1 — Aggressiveness

Controls how strict the filtering gates are. A safe investor sees only high-confidence, lower-volatility picks. An aggressive investor accepts lower GPS floors and a wider beta range in exchange for more picks.

Values: safe neutral aggressive

Default: neutral

Dimension 2 — Investment Timeframe

Controls which prediction horizon is used. The ML model produces four horizon outputs (1-week, 1-month, 6-month, 1-year). The timeframe setting selects the column referenced for recommendations, GPS patching, and the short label shown on cards.

Values: 1_week | 1_month | 6_month | 1_year

Default: 1_month

Data Model

TypeScript Types (src/utils/strategy.ts)

export type Aggressiveness = 'safe' | 'neutral' | 'aggressive';
export type InvestmentTimeframe = '1_week' | '1_month' | '6_month' | '1_year';

export interface UserStrategy {
  aggressiveness: Aggressiveness;
  investment_timeframe: InvestmentTimeframe;
}

export interface StrategyGates {
  confidenceFloor:    number;  // 0–100; minimum prediction confidence
  betaCutoff:         number;  // maximum beta tolerated
  gpsGate:            number;  // minimum GPS score
  predChangeGate:     number;  // minimum predicted change %
  envFloorMultiplier: number;  // <1 loosens, >1 tightens env-driven floors
}

export interface TimeframeConfig {
  outlook:              InvestmentTimeframe;       // outlook flag for predict_weighted_analysis.py
  predChangeMultiplier: number;                    // stacked on gates.predChangeGate
  sellThresholdShift:  number;                     // added to env-driven sell threshold
  mlGate:              number;                     // minimum positive predicted change %
  displayLabel:        string;                     // e.g. "in 6 months"
  shortLabel:          '1W' | '1M' | '6M' | '1Y';  // compact card label
  predictedPriceColumn:
    | 'predicted_price_1w' | 'predicted_price_1m'
    | 'predicted_price_6m' | 'predicted_price_1y';
}

export interface StrategyConfig {
  aggressiveness:       Aggressiveness;
  investment_timeframe: InvestmentTimeframe;
  gates:                StrategyGates;
  timeframe:            TimeframeConfig;
}

// Default applied when no row exists in user_investment_strategy
export const DEFAULT_STRATEGY: UserStrategy = {
  aggressiveness:       'neutral',
  investment_timeframe: '1_month',
};

getUserStrategy(userId)

Async function exported from strategy.ts. Queries user_investment_strategy for the given user. If no row exists, or if stored values fail validation (isValidAggressiveness() / isValidTimeframe()), DEFAULT_STRATEGY is returned. All callers wrap this with .catch(() => DEFAULT_STRATEGY) so a DB failure degrades gracefully to defaults rather than returning a 500.

// Actual implementation in src/utils/strategy.ts
export async function getUserStrategy(userId: number | string): Promise<UserStrategy> {
  const [rows] = await executeRawQuery(
    'SELECT aggressiveness, investment_timeframe FROM user_investment_strategy WHERE user_id = ?',
    [userId]
  );
  const row = Array.isArray(rows) && rows.length > 0 ? (rows[0] as any) : null;
  if (!row) return DEFAULT_STRATEGY;
  return {
    aggressiveness:       isValidAggressiveness(row.aggressiveness) ? row.aggressiveness : DEFAULT_STRATEGY.aggressiveness,
    investment_timeframe: isValidTimeframe(row.investment_timeframe) ? row.investment_timeframe : DEFAULT_STRATEGY.investment_timeframe,
  };
}

// Caller pattern
const userStrategy = await getUserStrategy(userId).catch(() => DEFAULT_STRATEGY);
Aggressiveness Gates

The AGGRESSIVENESS_GATES constant maps each aggressiveness level to a set of five numeric thresholds. These gates are applied to recommendation filtering across the portfolio, watchlist, and discovery scopes. Values shown are verbatim from src/utils/strategy.ts.

Gate safe neutral aggressive Description
confidenceFloor 65 50 35 Minimum AI model confidence score (0–100) required to include a stock
betaCutoff 1.5 2.0 3.5 Maximum beta coefficient — filters out stocks more volatile than this multiplier of the market
gpsGate 75 65 55 Minimum GPS score (0–100) required for a BUY recommendation
predChangeGate 3.0% 1.5% 0.5% Base minimum predicted price change (%) — multiplied by timeframe.predChangeMultiplier
envFloorMultiplier 1.05 1.00 0.95 Applied to env-driven baselines (GPS BUY, DISCOVERY). Safe raises the bar 5%; aggressive lowers it 5%.
envFloorMultiplier application: In GET /api/dashboard/recommendations, the env-driven thresholds (GPS_RECOMMENDATION_BUY_THRESHOLD, GPS_RECOMMENDATION_DISCOVERY_THRESHOLD) are multiplied by this value. Example: with buy threshold of 65 and safe aggressiveness, effective threshold = 65 × 1.05 = 68.25. The sell threshold is not scaled by the multiplier — sells use timeframe.sellThresholdShift instead, so users are always warned about underperformers regardless of aggressiveness.
Timeframe Config

The TIMEFRAME_CONFIG constant maps each investment timeframe to seven properties that affect the prediction column selected, the threshold scaling, and the UI label. Values are verbatim from src/utils/strategy.ts.

Timeframe outlook predChangeMultiplier sellThresholdShift mlGate displayLabel shortLabel predictedPriceColumn
1_week 1_week 0.5 -2 0.5% "in 1 week" 1W predicted_price_1w
1_month 1_month 1.0 0 1.5% "in 1 month" 1M predicted_price_1m
6_month 6_month 1.5 +3 5% "in 6 months" 6M predicted_price_6m
1_year 1_year 2.0 +5 10% "in 1 year" 1Y predicted_price_1y

Column interpretation

  • outlook — string flag passed to predict_weighted_analysis.py via the DeepMoney enrichment pipeline. Mirrors the timeframe key.
  • predChangeMultiplier — stacked on gates.predChangeGate. Final predChange gate = gates.predChangeGate × timeframe.predChangeMultiplier. A 1-week / safe user needs 3.0 × 0.5 = 1.5%; a 1-year / aggressive user needs 0.5 × 2.0 = 1.0%.
  • sellThresholdShift — added to the env-driven GPS SELL threshold (not multiplied). Long-horizon investors tolerate a lower GPS before calling a sell (positive shift raises the bar; +3 at 6M means they hold longer). Short-horizon investors sell sooner (-2 at 1W tightens it).
  • mlGate — minimum predicted change % for a DeepMoney pick to be validated by the ML signal in /api/prediction/deepmoney. Short horizons have a low bar (small moves matter in 1 week); long horizons require significant expected gain.
  • displayLabel — long, sentence-style label, e.g. "in 6 months". Returned by /api/dashboard/deepmoney-picks as timeframe_label for prediction-card copy.
  • shortLabel — compact two-char label ('1W', '1M', '6M', '1Y'). Returned as horizonLabel by the watchlist, portfolio, and recommendations APIs so the frontend can render "6M Pred" or "Based on 6M prediction" dynamically.
  • predictedPriceColumn — the SQL column in user_stock_predictions to use for the predicted price. Backs the suffix sfx ('1w' | '1m' | '6m' | '1y') which routes also use to read predicted_change_pct_<sfx> and confidence_score_<sfx> from the same row.
resolveStrategy()

Function signature

export function resolveStrategy(strategy: UserStrategy): StrategyConfig {
  return {
    aggressiveness:       strategy.aggressiveness,
    investment_timeframe: strategy.investment_timeframe,
    gates:                AGGRESSIVENESS_GATES[strategy.aggressiveness],
    timeframe:            TIMEFRAME_CONFIG[strategy.investment_timeframe],
  };
}

This is the primary consumer-facing function. It accepts a UserStrategy and returns a StrategyConfig bundle containing the resolved gates, timeframe config, plus the original aggressiveness and timeframe keys (handy for echoing back to the client as gpsHorizon or for analytics).

Universal usage pattern in API routes

// Every strategy-aware list endpoint follows this pattern:
const userStrategy    = await getUserStrategy(userId).catch(() => DEFAULT_STRATEGY);
const timeframeConfig = resolveStrategy(userStrategy).timeframe;
const priceColumn     = timeframeConfig.predictedPriceColumn;          // 'predicted_price_6m'
const sfx             = priceColumn.replace('predicted_price_', '');   // '6m'
const horizonLabel    = timeframeConfig.shortLabel;                    // '6M'

// SQL: select horizon-appropriate predicted price, change% and confidence
//      from a single row in user_stock_predictions
SELECT
  COALESCE(usp.${priceColumn}, usp.predicted_price_1m) AS predicted_price_horizon,
  usp.predicted_change_pct_${sfx}                      AS predicted_change_pct_horizon,
  usp.confidence_score_${sfx}                          AS confidence_score_horizon
FROM user_stock_predictions usp ...

// Threshold calculation (recommendations route)
const { gates: strategyGates } = resolveStrategy(userStrategy);
const mult                = strategyGates.envFloorMultiplier;
const buyThreshold        = envBuyThreshold       * mult;
const discoveryThreshold  = envDiscoveryThreshold * mult;
const sellThreshold       = envSellThreshold      + timeframeConfig.sellThresholdShift; // shifted, not multiplied
const predChangeGate      = strategyGates.predChangeGate * timeframeConfig.predChangeMultiplier;

// Response shape includes shortLabel as horizonLabel for the UI
return NextResponse.json({ ..., horizonLabel });
SQL-injection safety: priceColumn and sfx are derived from a controlled predictedPriceColumn enum in TimeframeConfig, so direct template-literal interpolation into the SQL is safe.
GPS Horizon Patching

The problem

GPS scores and their component breakdowns are computed once and stored globally (in stock_gps_scores) using the 1-month ML prediction as the mlpUpside component. If a user's timeframe is 6 months, the stored GPS score reflects a 1-month prediction, which is misleading.

The solution — adjustGpsForHorizon()

The function adjustGpsForHorizon(breakdown, predictedChangePctForHorizon, confidence?) in src/utils/gps.ts recalculates the mlpUpside (and, when supplied, the mlpConfidence) component using the user's horizon-specific predicted change and confidence, then recomputes the GPS total. The other components are timeframe-independent and pass through unchanged.

When it is called

Every list endpoint that returns GPS data to the client applies the patch per stock item, using the model's persisted per-horizon predicted_change_pct_<sfx> and confidence_score_<sfx> when present (so the patched score matches /api/prediction/[ticker] exactly). It falls back to a price-derived delta — ((horizonPrice − currentPrice) / currentPrice) × 100 — when those columns are NULL for legacy rows.

// Shared pattern in portfolio, watchlist, and recommendations routes:
const baselineBreakdown = item.gps_breakdown
  ? (typeof item.gps_breakdown === 'string' ? JSON.parse(item.gps_breakdown) : item.gps_breakdown)
  : null;

const storedChangePct  = item.predicted_change_pct_horizon != null
  ? parseFloat(item.predicted_change_pct_horizon) : null;
const storedConfidence = item.confidence_score_horizon    != null
  ? parseFloat(item.confidence_score_horizon)    : undefined;
const horizonPrice     = item.predicted_price_horizon     != null
  ? parseFloat(item.predicted_price_horizon)     : null;

if (baselineBreakdown) {
  let changePct = storedChangePct;
  if (changePct == null && currentPrice > 0 && horizonPrice) {
    changePct = ((horizonPrice - currentPrice) / currentPrice) * 100;
  }
  if (changePct != null) {
    const adjusted = adjustGpsForHorizon(baselineBreakdown, changePct, storedConfidence);
    perUserGpsScore     = adjusted.score;
    perUserGpsBreakdown = adjusted.breakdown;
  }
}
Why preferring the stored change%: The model persists predicted_change_pct_<sfx> and confidence_score_<sfx> at the moment of prediction. Reading them back is exact. Computing a delta from (horizonPrice − currentPrice) at request time uses a fresher live price but doesn't match what the model actually saw — fine as a fallback but second-best.

GPS Breakdown Modal — horizon label

The GPS breakdown modal receives a horizon prop ('1_week' | '1_month' | '6_month' | '1_year', default '1_month') sourced from the gpsHorizon field on each card. The ML Prediction row label is rendered as "ML Prediction (1m)", "ML Prediction (6m)", etc., so the user knows which horizon the displayed mlpUpside reflects.

The gpsHorizon field is part of the DeepmoneyCard, PortfolioCard, and WatchlistCard types (in src/app/components/cards/types.ts) and is forwarded through GpsTooltip → GpsBreakdownModal.

How the Strategy Propagates

Affected API routes

RouteStrategy use
GET /api/user/watchlist Resolves priceColumn, sfx, and horizonLabel from resolveStrategy(). SELECTs predicted_price_<sfx>, predicted_change_pct_<sfx>, confidence_score_<sfx> aliased as predicted_price_horizon / predicted_change_pct_horizon / confidence_score_horizon. Calls adjustGpsForHorizon() per item. Returns { watchlist, horizonLabel } with gpsHorizon on each item.
GET /api/user/portfolio Identical pattern to the watchlist endpoint. Returns { portfolio, horizonLabel } (where horizonLabel is the shortLabel: '1W' | '1M' | '6M' | '1Y') and stamps each holding with gpsHorizon.
GET /api/dashboard/recommendations Same SELECT pattern. Additionally computes buyThreshold = envBuy × envFloorMultiplier, discoveryThreshold = envDiscovery × envFloorMultiplier, sellThreshold = envSell + sellThresholdShift, and predChangeGate = gates.predChangeGate × predChangeMultiplier. Each recommendation carries gpsHorizon: userStrategy.investment_timeframe. The top-level response includes horizonLabel alongside recommendations and asOf.
GET /api/prediction/[ticker] On cache hit or refresh, computes gpsHorizon = strategy.investment_timeframe and derives horizonKey = investment_timeframe.replace('_', '') (e.g. '6month') to index result.predicted_change_pct_<sfx> and result.confidence_score_<sfx> for the horizon-specific GPS patch. The cache itself remains strategy-independent — only the GPS adjustment is per-user.
GET /api/dashboard/deepmoney-picks Reads user strategy to return timeframe (e.g. '6_month') and timeframe_label (displayLabel, e.g. "in 6 months") for UI copy on prediction cards.
GET /api/prediction/deepmoney Resolves outlook and mlGate. Cache key is bucketed by outlook (hot-tickers-enriched:{outlook}) so each timeframe has an independent 5-minute cache. Passes { outlook, mlGate } to analyzeStocks().
GET/PATCH /api/user/profile GET returns the full strategy object. PATCH accepts aggressiveness and/or investment_timeframe (nested under strategy or flat), merges with the existing row, validates, then upserts to user_investment_strategy.
scripts/update_predictions.py (DeepMoney sync) Loads all user strategies in one query (get_all_user_strategies) and applies the same gates + timeframe multipliers per ETF holding to populate etf_stock_recommendations. Constants live in scripts/strategy_config.py and must mirror strategy.ts.

Frontend consumption of horizonLabel

When watchlist, portfolio, or recommendations APIs return horizonLabel (e.g. '6M'), the corresponding card UIs render dynamic copy based on it instead of hardcoding "1M":

  • "6M Pred" column header on the WatchlistCard.
  • "Based on 6M prediction" in the recommendation rationale strip.
  • Compact pill on the PortfolioCard showing the horizon at a glance.

Profile API — Strategy Endpoints

GET /api/user/profile — strategy in response

The profile GET endpoint includes the full strategy in its response JSON:

{
  "username": "kevin",
  "accountType": "superuser",
  "strategy": {
    "aggressiveness": "neutral",
    "investment_timeframe": "1_month"
  },
  "stats": { "lookupCount": 12, "portfolioItemCount": 5, "watchlistItemCount": 3 }
}

If no row exists in user_investment_strategy, the response includes DEFAULT_STRATEGY values.

PATCH /api/user/profile — updating strategy

The PATCH endpoint accepts two body shapes (nested or flat). Either field is independently updatable; unset fields are preserved from the existing stored value via a load-then-merge step inside the handler.

// Nested shape (sent by the Profile component's aggressiveness save):
{ "strategy": { "aggressiveness": "safe" } }

// Flat shape (sent by the timeframe pill — optimistic update):
{ "investment_timeframe": "6_month" }

// Full nested update:
{ "strategy": { "aggressiveness": "aggressive", "investment_timeframe": "1_year" } }

// Response on success:
{ "ok": true, "strategy": { "aggressiveness": "safe", "investment_timeframe": "6_month" } }

Upsert behavior

The route loads the current stored strategy first (via getUserStrategy), merges the incoming fields, validates the combined values with isValidAggressiveness / isValidTimeframe, then runs an INSERT ... ON DUPLICATE KEY UPDATE against user_investment_strategy. A partial PATCH that sends only aggressiveness will not reset investment_timeframe to the default.

A labeled <select> dropdown with a hint text line underneath. Changing the value marks the form as dirty (isDirty). The "Save Strategy" button is only enabled when the value has changed from the original. On save, the entire strategy object is sent as a nested PATCH body.

Python Mirror (scripts/strategy_config.py + update_predictions.py)

The batch prediction script update_predictions.py uses an exact mirror of resolveStrategy() logic via scripts/strategy_config.py. When computing per-user ETF holding recommendations, the script loads all user strategies in a single query (get_all_user_strategies()), then applies the same aggressiveness gates and timeframe multipliers to decide whether each ETF holding crosses the recommendation threshold and which predicted_price_<sfx> column to read.
